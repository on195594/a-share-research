## 当前部署

生产数据库为 **v26**（11-23 由 `51b1c61` 发布，新增 `scheduled_runs`），判断契约 **8**，生效政策激活记录 **32**（政策身份 schema 3，11-23 由 `695a36f` 发布按原参数自动激活）。模型只经 `agent-runner/` 调用，配置在[模型配置档](../a_share_research/model_profile.json)：作者 `openai-codex / gpt-6.2-sol / medium`，复核 `openai-codex / gpt-6.1-sol / high`。12-01 月批沿用此配置档与契约 8，11-18 主模型切换前后的报告分开记分。

回退须保留 v26 数据库与新账本。上一个生产镜像 `695a36f` 是 v25，其 `/ready` 拒绝 v26：回退到它时先恢复发布前备份 `backup-pre-51b1c61-20261123-163912` 并补回之后的新增写入，再在 `695a36f` 上运行 `install.py --apply` 装回旧脚本，并从证据目录 `sched-state-20261123/` 放回本地状态文件（保持 0600）。冻结窗口内只是脚本出问题时，不动镜像，在 `695a36f` 上运行 `install.py --apply` 装回旧脚本并放回状态文件即可，旧工具仍在注册表中；当天已提示的止损档位与机会可能再推一次。回退时按[部署入口](../README.md#回退)重新发布上一个提交的镜像。`4881ad1` 之前的镜像不认 schema 3 政策身份，回退越过该提交时须先恢复其发布前备份 `backup-pre-4881ad1-20261121-120608`，再补回之后的新增写入；优先前向修复。回退越过分层重构第 2 步时，旧镜像读 `MODEL_*`，须先在 `.env` 按配置档补回这些键。发布带库迁移时，先按授权恢复发布前备份，再补回备份后的新增写入。回退到段 1 的 v25 镜像时，还须撤下 nginx 的 `/mcp` 路由并恢复对应的[宿主客户端备份](../ops/clients/README.md#段-2-切换回退)。需要关闭 Web 账户写入时，撤销 `web-owner-proxy` grant #13。

## 待真实事件的验收

**12 月首跑最小验收（12-01 至 12-04）**

1. 核对 MCP 定时提交时间、实际回执、唯一批次 ID 和 `screen-v1.3` 快照。核对 Q20、S10 分池名单及每只候选的复用报告、新研究或失败记录。
2. 核对每项研究最多 21 次调用，三项比较或排序各最多 2 次，整批最多 636 次。标明缺失的调用用量。
3. 核对 L5、SL3 共同冻结时间和缺口，再查下一交易日共同入场、未成交现金席位、基准和首次收益。
4. 核对 Telegram 实际送达与去重，不另建批次。验收后清理本次月批核验提醒任务及脚本。

其余观察由真实事件触发，未给定截止日的项目不阻塞发布。

- **账户与调度**　核对 MCP 扫描、止损和 12-01 月度对比的首次自然执行，以及 11-27 新政策身份下的止损检查与日报。实盘触发止损或账户快照提醒时核对正文送达，盘中发布时观察止损暂停宽限与恢复。核对五宿主模型实际调用账户工具的结果及 AGY 登录。生产首次成功评估 NAV 区间时核对成功页和 H00906。所有者登录时核对 GitHub 登录与 30 天记住设备。
- **报告阅读与复核**　在真实手机及 Safari 上观察生产登录后的性能、读懂报告是否在两分钟内。agent-runner 上线后的生产首跑 run 255（11-22）首轮复核通过；继续核对头 5 份报告的复核通过率、失败分类与引文核验。抽查首批五份报告的 `open_questions` 有无漏过实质缺陷，检查契约 4 之后首批报告的否定词和复核修正轮数。按风险事件逐条核对首批接续报告的公告引用，统计 `unable` 和 `open` 比例。
- **数据缺口**　上游额度恢复后核对卖方覆盖窗口，待行情可用时复核监控评估标明的行业涨跌幅缺口。逐值公告映射、历史估值分位及波动指标、报告阅读后续与行业背景按[基本面升级方案](investment-upgrade.md)待确认。
