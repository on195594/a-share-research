## 4. I2：质量基线与升级比较

Research 复用 `research.py` 的 `EVAL_SET`、现有确定性测试和真实材料；Skills 复用 `docs/agent-behavior-eval.md`、现有 capture 脚本和行为评估测试。Lib 继续按自己的测试和发版清单验证公共计算。

交付：

- Research 建立当前版本的 10 家非金融公司及 1 家范围外公司的基线，记录通过率、错误类型、耗时、调用次数和人工抽读结果。
- 区分实时取数端到端验证与固定真实材料的模型对比。后者冻结文档、财务表、行情时点和输入身份，避免把数据变化算成模型改进；不造合成研究资料。当前 `execute()` 每次先调用 `gather()`，尚无离线材料重放入口；本工作包最小增加从已保存真实材料恢复 `Material` 的入口，复用现有成文、检查、复核和修复函数，重放时不重新取数。材料不足时显式记录缺口，不用当前数据补齐历史输入。
- Skills 对当前候选 Skill/runtime 与目标宿主重新验证适用案例，包含追问不随意改变动作、账本差异、已有材料复用、关键引用缺证据等。记录候选 Skill/runtime 版本、目标宿主及模型身份，未知身份显式标未知。已有历史捕获保持原身份，未执行项记录为未验证。
- 从真实失败中增加少量脱敏案例，保留未参与提示词调整的案例；程序检查、模型评价与人工抽查分别记录。

基线验收：当前版本的材料、版本、结果、错误类型和未验证项完整记录并可关联。固定材料可重放；不可重放的历史案例列明缺口，不计入同材料比较，也不能替代候选采用所需的必需评估。发现错误可以冻结为基线，另列修复项，不要求先消除错误才记录现状。

候选采用：不低于基线及现有验收底线，适用边界案例无违规，被采用候选没有已知关键事实错误。Research 模型候选先以少量真实困难案例筛查，采用前覆盖 11 家评估集及比较前确定的适用真实留出案例；固定材料比较与实时取数验证分别记录。Skills 候选覆盖其既有八个行为场景及本次变更适用的多轮案例。结果波动或失败时才做有依据的补测，遵守现有模型/provider 限制，不重复不变的失败运行。

回退：保留基线及旧候选结果，恢复已验证模型/提示词或成对 Skill/runtime；不修改旧捕获哈希冒充新验证。私有输入、完整运行日志和账户资料不进入 Git，仓库内只保留适合提交的脱敏样本和测试。

## 5. I3–I4：只读证据复用

前置问题必须具体到“哪个宿主、哪个问题、哪份现有报告需要复用”。Research 实现生产者，Skills 维护消费步骤；合同依据[项目契约](project-contract.md)的最小证据要求，在 I3/I4 联合交付中定稿。I3 代码可单独评审，接口在首个消费者验收前保持草案状态；两者以联合验收通过作为完成条件。

I3 最小交付：读取指定公司/报告、定位报告内引用原文或数据字段。先复用现有报告 `body` 和按哈希保存的文档，仅实现首个场景所需入口；传输从现有 CLI 或 API 中选择，MCP 仅在宿主接入确有需要时增加。

读取端使用真正只读的存储路径。当前 `db.connect()` 会建目录、建表并设置 WAL，不能直接把它当成零写入读取接口。明确数据库不存在、报告不存在、未知合同版本、原文缺失、失败报告和时效不足的输出，不在读取时建库、修复、刷新数据或提交研究。

按实际 SQLite 版本和部署挂载验证 worker 未运行、正在写入以及只读挂载时的行为，覆盖 WAL/SHM 文件已存在和缺失的情况；读取条件不足时明确报错，不为读请求扩大目录写权限，也不把正在变化的数据库标为 immutable。条件依据 [SQLite 只读 WAL 文档](https://sqlite.org/wal.html#read_only_databases)，实际环境结果在 I3 实施时记录。

I4 最小交付：Skill 在相关任务中复用已有证据，只有关键缺口才按原有预算补查官方披露。报告不能代替当前行情、风险门和账户快照；覆盖不足时显式保留缺口。QA 继续只检查其支持的研究正文，不沿用上游报告的“通过”来跳过自己的适用检查。

联合验收：

- 从一个真实用户问题读取报告、展开原文并形成可核查回答；记录取证次数和人工核对结果，确认复用收益。
- 覆盖错公司、缺报告/原文、未知版本、过期、复核失败及部分材料可用；历史证据与当前判断分开。
- 证明只读请求不创建数据库、不改变任务/研究/账户状态、不触发模型调用或 W1。worker 写入报告期间，读取须在同一快照中核对任务终态与报告核验标志：`done` 且 `passed=1` 才交付已复核结论；`failed` 且 `passed=0` 可交付已有的已核验事实和失败原因；运行中、无报告或状态不一致时明确未就绪或不可用，不暴露未完成结论。
- 研究应用的旧网页流程仍可用；Skills 在无接口或接口失败时保持独立运行，并按原有显式缺口处理规则结束或取证。
- 宿主实际跑通后才标为集成通过；离线合同测试不能替代宿主验证。任何客户端安装或激活沿用原项目授权要求。

测试沿用各仓约束：Research 使用真实采集产物；Skills 使用隔离 fixture 和行为验证；集成采用真实宿主只读流程。回退只撤销新消费入口/适配，保留原始报告和账户数据。

## 6. I5–I6：自主取证与持续复核

I5 从一个明确的失败类型开始，由现有宿主 Agent 选择取证步骤。输入包含研究问题、已有证据和缺口；工具、调用上限、停止条件沿用并补齐当前任务需要的约束。结果仍通过确定性检查与适用复核，状态更新仍走原有写入门禁。

采用条件：在相同真实材料和留出案例上改善目标问题，其他已知质量与权限边界不回退；耗时和调用增量有实际价值。失败时回到已验证流程并说明缺口。未满足条件时停止该工作包，不通过增加重试或扩大检索掩盖原因。

I6 先支持手动提出“新增信息是否影响旧判断”并展示带证据的比较结果，不依赖 I5 自主取证。需要持久化时，公开研究复核记录归 Research；账户分析、决策或监控状态归 Skills runtime，只有具体用户确认后才按 W1 与 `--confirm-write` 写入。纯展示不要求新增记录。

需要新研究时由用户在 Research 的现有网页或 CLI 发起。任何跨项目任务提交接口，须先补齐[项目契约](project-contract.md)第 3、4 节的任务所有权、触发授权及重复请求语义，不能通过只读查询隐式创建任务。手动复核验收后，只有触发频率、来源和受影响范围明确时才考虑计划任务与通知；重复事件不重复产生持久动作。人工纠错进入脱敏评估，不直接改生效投资政策。

若确需 Research worker 调工具、长任务恢复、定时研究或新增平台，先明确其对当前项目契约和产品范围的变化，再按已有授权实施。回退时停止新增触发/消费路径，保留历史证据，不回滚账户事实。
