1. **迁移时机与备份**：`db.connect()` 每次连接都执行 `CREATE TABLE IF NOT EXISTS`；新 web 导入和 worker 启动都会新增 `research_progress`、`progress_calls`，不修改原有表/报告。即使只运行进展 CLI 的读取命令，首次连接旧库也会建表。ARM 操作者须先确认数据库备份、队列空闲和建表窗口，再让候选连接生产库；备份用 SQLite backup 一致快照，不能只复制可能仍有 WAL 的主文件。当前固定发布工具明确只负责镜像切换，不是迁移工具；其空闲检查及表指纹也尚未覆盖这两张表，不能把该工具成功解释为进展任务已空闲或已核验。此处不提供临时 SQL，不在当前环境执行迁移。
2. **回退范围**：本次只有附加表，旧应用不引用它们；从源码看，保留新表可恢复旧镜像继续读原报告，尚未在生产实测。回退前先停止新的进展提交并核对现有 `queued/running` 及调用预留状态；有在途/结果不明的调用先保留证据、停止切换，不能当作未调用。旧 worker 不处理这些任务，恢复新 worker 后 `queued` 会继续、`running` 不会自动重试；不能删记录或改状态规避限额。保留表与日志，不因应用回退恢复旧数据库而丢掉上线后的研究；若需整库恢复或清理，另作数据回退决策。
3. **调用入口与成本**：部署、公司页 GET、刷新和返回不创建进展任务。有效关联但无记录时，已登录 owner 可通过 CSRF 表单显式排队；已有 Bearer Key 可调用 POST，沿用现有授权，无新增角色。没有功能开关、报告白名单或全局四次调用计数器；输入指纹唯一键、原子领取、阶段唯一键只保证每个输入版本最多生成一次/复核一次。新版本输入会有新指纹。上线验收只能提交报告 44 与 42，各一次；不提交关联追问或其他研究，先核对已有状态再操作。worker 空闲时消费已排队任务；失败/中断不自动重试，`started/failed` 也可能消耗供应商调用，预算不能清零。
4. **结果导入**：现有 `progress_import` 只将完整原报告导入尚不存在的隔离库，不导入 `research_progress` 或 `progress_calls`，也拒绝已有生产库。没有正式的已审查比较结果生产导入/重新绑定工具。不能复制表、临时写 SQL 或伪造 `passed`。本轮按新指令直接在生产用限定预算生成；若以后要迁移隔离结果，须单独实现并审核输入哈希、契约版本、两份报告身份、复核及调用账本校验。
