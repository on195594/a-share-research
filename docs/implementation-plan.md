## 5. I3–I6：最小完整研究流程（本批设计）

### 模型与证据

沿用 pi `completeSimple` 的原生工具声明、assistant/toolResult 消息续接；Python 执行有限领域工具。模型与行情凭据仅在 worker。工具不接收任意 URL、SQL、文件路径或 shell，不让披露中的指令获得工具权限。

- 列出公司定期披露；AI 选择文档，按关键词检索/页码读取。范围覆盖当前采集器的年报、半年报、季报，可对比同业；PDF 页码、标题、公告日期、哈希与读取范围均入材料快照。
- 查询已有 Provider 的财务与行情字段。增加上年同期数据支持可比分析；同业数据带公司身份。缺值保持缺失，不用零补齐。
- 用引用的数据行和期间作输入，由程序计算差额、增速、比率或加总；保留输入、公式、单位与计算结果作为新引用。比率单位、期间可比性及负基数增速有显式处理，语义仍交复核检查。
- 直接回答和报告用同一套引用；原文检查按 source/page 匹配，派生数字按计算记录核验。保留原有独立复核请求和最多两次修复，不默认增设评审 Agent。

风险、业务和财务不设固定条数，按证据重要性决定篇幅；结合新旧披露区分风险是否仍然存在。复核通读后一次列全实质问题，避免每轮只补报一项。原文论断结合已引用页面的表头、行名和上下文核查，不因短摘录未重复表头而阻断；数字、主体、期间错误及断章取义仍属实质问题。真实纠错任务与内部修复分开提示，普通报告不生成虚构的“此前反馈”。

探索最多 12 轮、24 次工具调用，时间预算 15 分钟；在每轮和工具调用前检查，在途模型请求受单次 10 分钟及整体剩余时间限制，在途取数/解析沿用各自网络与子进程超时。相同请求复用已取得结果；无新增证据时结束探索，保留缺口。整体调用时间预算 30 分钟（不是在途 I/O 的秒级抢占保证），另留最多 6 次成文/核验/修复空间，沿用明确失败状态，不静默退回旧结论。工具失败保留诊断日志并记录为缺口，原有材料可用时继续；凭据/模型故障按失败记录。最终材料和调用记录可关联，冻结材料重放禁止重新取数；旧快照继续用已有成文路径，明确未重新评估探索策略。

### 共用入口与合同

| 入口 | 作用 |
|---|---|
| `POST /api/research` | `code`、可选 `question`、必填 `request_id`，可选同公司 `parent_report_id`；创建任务，返回 ID |
| `GET /api/runs/{id}` | 状态、步骤、错误、关联报告 ID；不含调用提示词或凭据 |
| `GET /api/reports?code=...` | 公司报告列表、状态与时间 |
| `GET /api/reports/{id}` | `research-v1` 信封中的报告、证据、范围与缺口；引用可定位原文和计算 |
| `POST /api/reports/{id}/feedback` | `request_id`、具体 `location`、`text`；创建关联核查任务，不覆盖原报告 |

API 用宿主 CLI 签发的短期 Agent bearer token，复用现有会话存储但与浏览器 cookie 用途隔离，默认 60 分钟、最多 8 小时，可撤销。它只授权本人的研究查询/任务/反馈，不授予账户或管理权限。网页继续 cookie、CSRF 与同源验证；`/api/*` 只接受 bearer、忽略 cookie 会话，不用放宽网页 CSRF 来适配 Agent。错误以 JSON 与正确 HTTP 状态返回。

网页表单和 API 共用创建逻辑。重复请求在数据库唯一约束下原子处理；同编号但公司、问题、父报告或反馈不同返回 409。父报告不存在或跨公司拒绝，输入长度设合理上限。带问题或父报告的请求不受当天报告提示拦截；反馈 location 必须对应原报告实际段落/下标，否则返回 4xx。GET 只查询，不建任务、不补资料、不调用模型；应用启动沿用既有数据库初始化，不增加只读挂载客户端或 WAL 验证矩阵。

报告与任务由一次 SELECT 快照关联：`done` 且 `passed=1` 才返回已复核结论；失败仅返回现有核验事实与原因；进行中或状态不一致返回未就绪。旧报告可读，缺少的来源/身份明确标未知，不能把旧行情当当前数据；请求未知合同版本返回错误。接口不导出会话、完整模型日志或私有配置。

### 追问与反馈

追问持有原报告 ID，新运行重新核对当前材料，原报告只作为待复核上下文。纠错关联 `location`（例如 `financial[0]`）及用户说明，用同一任务流程判断成立与否、解释根因、给出修正与剩余缺口。两类任务与原报告一起展示；不得将后续失败覆盖成原报告成功或改写旧结论。

同公司已通过复核的纠错可供后续研究作线索。记录反馈、核查与改进建议即可，不新建知识库、自动优化器或复杂候选状态机。实际代码/提示修正走正常小差异、相关真实样本、采用/回退流程；本批至少走通一条真实纠错至核查结果，并明确能否修复或仍缺什么证据。对投资规则的挑战作为研究假设，账户政策仍由 Skills owner 决定。
