## 验证与交付规则

| 变更 | 验证 |
|---|---|
| 文档 | 路径、锚点、职责与状态一致，`git diff --check` |
| 确定性代码 | 运行受影响测试及一个正常案例；同一源码与依赖的已通过结果直接沿用，仅因新改动、失败或明确的未覆盖风险扩大范围 |
| 研究流程 | 受影响真实案例 + 1 个正常案例；仅切换模型或全局成文/复核契约时跑一次评估集，见[产品方案第 8 节](proposal.md#8-开发方式) |
| 页面 | 本机真实浏览器、手机尺寸走主流程 |
| 跨项目接口 | 生产者/消费者合同、只读查询无研究副作用、真实 Agent 主流程、失败与回退；Skills 按其 development，Lib 按其 RELEASE_CHECKLIST |

固定材料重放不等于重新取数；历史捕获不证明当前候选。出现失败或新改动才补测，记录采用或拒绝的依据。发布使用 [README 固定流程](../README.md#部署)，不自动重复研究或整套回归；纯文档不重建镜像。交付区分代码、测试、发布、客户端激活和生产验收。当前部署状态只在本页维护，其他文档保留功能与边界并链接本页。备份保留与证据清理遵循[积累方案 K4](research-accumulation.md#k4-存储保留针对-p1-后半)，不自动删除。
