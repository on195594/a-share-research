# 合一重构方案

更新：2026-11-13。把 `a-share-research`、`a-stock-agent-skills`、`a-stock-lib` 合成一个仓库、一个账本、一套工具。**本方案已于 2026-11-12 完成实盘割接与生产上线（第 4 段次日观察与旧仓归档收尾按实施计划推进）**；现行系统边界见[系统架构](../ARCHITECTURE.md)，生产部署与后续观察见[实施计划](implementation-plan.md)。本文件保留核心设计决定、不变量与验收基准，历史演进细节沿 Git 追溯。

分类：基础设施重构。直接产出是账户与判断同库、任何入口的判断过同一个核验、投资规则成为可对照的政策版本；不宣称投资收益改善。

第 1 版（`f8321e9`）经 Codex 独立审查发现 7 项阻断问题，本版逐项修订；报告在仓库外 `~/.local/share/a-share-research-evaluations/consolidation-review-20261111/report.md`。

## 1 为什么合一

代价都落在三仓的接缝上：

- 两个数据库：判断与交易对不上（2026-11-11 实测 25 笔买卖 0 笔关联报告）。
- 两套研究流程：宿主 Agent 在 Skill 里得出的公司结论不经引文与计算核验，也不进判断账本。
- 两套指标与一套发版仪式：PE 分位两端定义不同；Lib 每次发版打 wheel、锁哈希、两端回归，而 Research 只用它 3 个符号。
- Skills 的测试（2.2 万行）与说明文字（7700 行）多于运行代码（1.7 万行），账户库只有 37 条事件、10 条持仓。

## 2 不变量与所有者决定

三条不变量，其余都可以改：

1. **真钱只由所有者动**。系统不下单；账户数据不丢、不错。
2. **冻结的判断不改写**。已冻结的预测、批次、记分规则与判断契约面不动。
3. **事实可溯源、计算经程序**。任何入口写入判断都过同一个核验。

所有者 2026-11-11 决定：

| 编号 | 决定 |
|---|---|
| D1 | 合并数据库，归档 Lib 与 Skills 两个仓库 |
| D2 | 记账从逐次确认改为“对账通过即入账，对不上才问” |
| D3 | 现行投资规则原样作为政策 v0；此后换政策由所有者切一次指针 |
| D4 | 交易归因分成两个概念：成交入账时填写的“显式依据”进记分；自动推导的“成交时可用研究”只看覆盖率 |
| D5 | 原定月批后切换；11-12 所有者明确改为当日轻量验收切换，月批与连续运行改为后续观察（第 5 节） |
| D6 | 读过账户的凭据产出的外部研究单独标识、单独记分，不称为盲研究 |
| D7 | 分析状态（L3、预警、Tier、论点版本）先改为追加历史，再取消逐次确认 |

本方案范围内的数据库迁移、compose 服务与挂载、Hermes 任务调整和宿主客户端安装随上述决定一并授权。每段以第 5 节的退出条件为准，未通过的段顺延，不以放宽对照或跳过回退来保日期。

## 3 目标结构

```
a_share_research/
├─ （现有模块）   研究、核验、估值、记分、网页、worker
├─ core/          并入的 Lib：数据 Provider 与确定性计算
├─ account/       新写的账户账本：事件、入账、投影、可用研究诊断
├─ policy/v0/     旧 Skills 运行时整体，作为政策 v0；只替换传输与数据库连接
├─ tools/         工具注册表、tools 进程、CLI 客户端
└─ gate.py        入账门
skill/a-share/    唯一的 Skill
ops/hermes/       全部定时脚本
```

依赖方向固定为 `policy → account → core`，现有研究模块只依赖 `core`。现有研究模块不为目录整齐而搬动，但允许清单内的必要适配：`sources.py`、`market.py`、`stock_codes.py` 的旧包导入和 `model.py` 的运行身份改指 `core/`。

### 3.1 政策 v0 是旧运行时整体

旧运行时的模块互相调用（持仓命令同时依赖数据库、研究读取和政策；仓位计算导入持仓命令），按目录拆分得不到“原样”。因此整个包进 `policy/v0/`，只做三处替换：研究卡片读取由 HTTP 改为进程内调用（`monitor_research` 的分类与板块规则保留）；数据库连接、路径与迁移改由本仓库 `db.py` 提供；A—F 阈值随包进入 v0，不放 `core/`。

- **执行方式**：`tools` 进程以子进程运行 v0 命令（参数列表，不经 shell），保留原有输出与退出码。旧代码的进程级只读开关、`fork` 超时调用和 `sys.exit` 因此不进入长驻服务。
- **政策身份** = 代码哈希 + 参数（现 `risk-policy.json`）+ 规则哈希 + 指南版本；每次评估结果带身份保存。
- **指南**：三个旧 Skill 的规则资料原样进 `policy/v0/guide/`，默认保留，删除须有影子对照依据。唯一的 Skill 从当前生效政策发现指南，不写死 v0。
- **v0 的输入口径冻结**，包括它实际生成的 5 年与 10 年两套 PE 百分位；口径统一由新政策版本完成。
- **表**：账户与政策表沿用原表名进入同一个 SQLite（与研究表无重名），补 `company_key`；结构由本仓库迁移拥有（迁移 v10）。账户表的 `company_key` 允许为空，因为历史分析里有非 A 股代码。逐表逐列的去向以 `account/mirror.py` 的清单为准，镜像每次运行先核对来源结构与清单一致；来源的 `schema_migrations` 表和 `analysis_results.data_date` 列（无读者、全为空）不迁移。
- **生效指针** `policy_activations` 只追加，只能由所有者登录后的网页或本地命令切换，页面显示当前版本与生效时间。

新政策（v1 起）直接写在 `account/` 与 `core/` 之上，实现 `evaluate(账户状态, 行情, 论点卡) → 动作、复核项、仓位`。

### 3.2 账户账本与对账入账（D2）

`account/` 是新代码。事件只追加：

| 字段 | 含义 |
|---|---|
| 业务身份 | 券商成交编号；没有时用账户、日期、代码、方向、股数、价格与成交时间的规范化组合。同一业务身份只入账一次 |
| 入账批次与期初版本 | 一次提交是一个批次，声明它对账所基于的账本版本；版本已变则拒绝并返回当前状态 |
| 幂等键 | 批次内容哈希；重复提交返回原回执 |
| 证据引用 | 截图或交割单按内容哈希存入数据目录（与 PDF 同样进备份）；哈希只证明材料来源，不用于去重 |
| 显式依据 | 可选的报告 ID（D4） |
| 作废引用 | 更正 = 作废原事件 + 追加正确事件；投影忽略已作废事件，不用负数冲销 |

入账是一个事务：检查业务身份去重、逐只股票“期初 + 买 − 卖 ± 送转 = 快照股数”、现金变动与成交净额/分红/费用一致、持仓市值 + 现金与总资产之差在容差内，全部通过才追加并重建投影。结果只有四种，且都返回可查询的回执：**已入账**（新增、重复、作废各几条，前后股数与现金）、**缺材料**（缺哪一项）、**对账冲突**（逐项差异）、**服务失败**。截图不含完整成交时走“只更新资产观察”，不追问成交历史。容差在影子期用真实截图实测后写入政策参数。

**投影**：旧表形状的 `holdings`、`holding_events` 由事件确定性重建，v0 读投影；切换后 v0 的买卖记账命令停用。

**分析状态**（D7）：L3、预警、Tier、论点版本改为追加行，当前值取最新一行；Agent 直接写入，带证据，不再逐次确认。现行 L3 更新是覆盖旧值，这一步先于取消确认完成。

### 3.3 交易与研究的关系（D4）

- **显式依据**：成交入账时由当时的会话填写报告 ID，沿用现行校验（同公司、已通过复核、不晚于成交日）。只有它进入“研究支持的交易”记分；买入、卖出、止损与再平衡分开统计，止损和再平衡可以没有依据。
- **成交时可用研究**：查询 `account.trades.research_available_at_trade`（沿用[数据层方案](data-foundation.md)不建数据库视图的做法），按成交日推导同公司最近一份已通过的报告，只用于覆盖率诊断；同日报告无法定先后，不进任何因果统计；没有匹配时写“未找到本系统事前报告”。当前数据为 5 笔有、20 笔无（均早于首份报告）。
- 历史 25 笔只进后者，不回填依据。

### 3.4 工具与凭据

一份注册表。每个工具声明名称、版本、输入输出结构、错误格式、读或写、是否幂等；三种出口执行同一权限检查。

| 出口 | 用途 | 说明 |
|---|---|---|
| worker 进程内 | 研究 AI | 沿用现有 `TOOLS` 定义，不重写 |
| `tools` 进程 | 宿主 Agent、Hermes | 同一镜像的第三个服务，只听 `127.0.0.1:8621`；单独的环境文件，只含行情凭据；限 CPU 与并发 |
| `ashare` CLI | 不支持 MCP 的宿主、脚本、人 | 单文件、只用标准库，调 `tools` 进程 |

| 凭据类型 | 能调用 | 产出的外部研究 |
|---|---|---|
| research | 研究工具、报告与论点卡读取、外部研究的开启与提交 | 计为盲研究 |
| assistant | 上述全部，加账户与政策工具 | 标记“账户知情”，单独记分（D6） |
| owner | 政策切换、Key 管理 | — |

程序只能保证凭据级隔离，管不了宿主会话里已有的上下文，所以盲研究只对 worker 和 research 凭据成立。现有 Key 默认为 research。

### 3.5 入账门与外部研究

外部研究是独立的运行类型，状态为 取证中 → 已提交 → 复核中 → 完成或失败：

- 取证中：research 工具把材料记入该运行，运行归属创建它的 Key。
- 提交：原子冻结草稿与材料，记录两者哈希；机械检查同步返回逐条问题；同一内容重提返回原回执，修改后重提生成新版本。
- 复核：worker 按类型分派，对已提交的外部研究只做独立复核，不重新取证成文；排在所有者提交之后、批次之前。重启后未完成的复核回到已提交。
- 入账：报告记录生产者与是否账户知情。记分先按生产者筛选再去重；冻结实验的样本池不含外部研究。任务查询、发布核验与记分加载器同步适配。

外部研究的排队在月批保护期内不启用。

**受控新取证的完整范围**：外部 Agent 可以研究本系统从未研究过的公司，不能把“已有 worker 材料”设为永久前置条件。保留 `external.start(source_run_id)` 的复用入口，另以 `external.open(request_id, code)` 持久登记初始化操作；HTTP 只校验身份与参数，worker 经现有 `material.gather` 实际取得公开材料，不调用模型、不创建伪造的 research run。客户端用 `external.operation(operation_id)` 查询，成功时才原子创建有完整种子的外部研究并绑定操作结果。首次研究的 `source_run_id` 为空，材料和哈希仍不可空；金融公司、无有效年报、取数失败均保留明确失败，不造空种子。开启方式纳入请求身份，同键不同意图冲突，失败重试返回原操作，新尝试使用新键。

种子材料保持不可变；后续 `external.acquire` 经原工具白名单取证、读页和程序计算，追加完整材料版本与父版本、操作身份和哈希。材料版本与草稿提交版本分开；同一外部研究的取证串行执行，不能拼接两个并发分支的 D/C 编号。提交显式绑定材料版本和草稿，按“草稿哈希＋材料哈希”去重：同稿补证后是新提交，原稿原材料重试仍返回原回执。后续取证不得改变已提交版本的复核输入；复核与发布都读取该次提交绑定的材料，不能读取当前最新材料。旧材料默认版本 0，旧 ID、原文、哈希、回执和复核关系保留。

初始化与后续取证共用持久操作生命周期，记录调用 Key、规范化参数、开始与截止时间、结果或安全错误。网络/PDF 工作在短数据库事务之外，以可终止的受监督子进程执行；HTTP 断连不重建操作，超时、重启或撤销凭据不发布半份材料。执行前和落库前再次核对身份、执行权及材料版本；来源标签在请求时固定。发布空闲检查、暂停排空和备份须覆盖这些操作及全部历史材料引用的 PDF。参数严格遵守已有工具定义，不接受自由 URL、文件路径、SQL、原文页或替换快照作为可信输入；原研究工具和冻结契约面保持原语义。

此合同需新增材料版本与操作存储，并调整提交唯一约束、首次来源可空性、复核/巡检/备份读取。实施时必须同步数据库协议、旧镜像拒绝与首次生产迁移目标；既有 v9→v21 演练不能作为新目标的验收证据。先备好能读写新协议的兼容恢复镜像，再用正式入口重新验证迁移守恒和保留新库的恢复。具体完成状态归实施计划，以上不代表接口已经实现。

### 3.6 Hermes 与一个 Skill

全部定时脚本进 `ops/hermes/`，包括现在只在宿主上的三个 `a-stock-*` 包装脚本。迁移表逐任务列出脚本、调用命令、去重状态、超时与回退入口；`a-share-advisor.py` 中的旧持仓与监控快照调用一并替换。通知的时间与数量不变。

没有 TuShare 替代的 AKShare 调用只有国债收益率一处，AKShare 依赖随 v0 保留。源码按固定提交复制进来（Lib `7bda9cd`、Skills `1f7c520`），历史留在归档仓库。

**量尺**：旧账户代码的基准是沪深 300 与中证红利全收益，北极星是中证 800 全收益。保留旧对照，新增账户净值对 `H00906.CSI` 的口径，不改写旧报表。

净值的首版确定性口径为 `unit_nav_v1`，服务于复盘改进：先排除外部资金流对收益的影响，再比较同期间累计收益；它本身不是判断记分或盈利改善证据。仅覆盖人民币现金与股票、无负债且无证券转入转出的完整账户。期初份额等于期初资产、净值为 1；每笔入金为正、出金为负，以该笔发生前同一时刻的完整资产估值除以原份额得到净值，再按现金流调整份额；期末资产除以剩余份额得到期末净值。买卖、分红、手续费及税款留在实际资产变化中，不作为外部申赎。依据为[真实时间加权收益的分段链接方法](https://www.gipsstandards.org/standards/gips-standards-for-asset-owners/gips-standards-handbook-for-asset-owners/)，不是 GIPS 合规声明。

首版要求起止点都为上海时间 15:00:00 的完整收盘估值，且 `H00906.CSI` 原始响应有两日的精确收盘值；不把盘中估值移到收盘、不用相邻日填缺口。指数归一化为期末/期初，超额字段是账户累计收益减指数累计收益的百分点，披露账户已发生费用与指数全收益的差别。调用者显式选择观察或已入账快照并说明理由，不按最新记录时间静默解决冲突。每笔外部流量须严格位于两个端点之间，提供流前估值；同刻多流、流前流后含混、资金流耗尽账户份额时拒绝此段，需另选有完整材料的区间。暂不提供 Modified Dietz 近似或跨清零账户的连续曲线。

资金流水完整性必须以覆盖精确区间的声明和原始凭证提供，即使声明零出入金也不能省略。声明绑定包含原批次、事件、作废关系与资产观察的资料哈希，纯新增观察也使新请求的旧哈希失效；有效 deposit/withdrawal 必须逐笔匹配，已包含资金事件的入账快照不能充当其流前估值。声明是有出处的调用者陈述，不等于程序认证券商完整历史；结果始终单列 `trade_history_acceptance=not_assessed`。输入与结果以内容哈希保存到既有私有证据目录，可在后续更正后重放旧包，哈希只证明内容一致，不证明券商或行情供应商身份。公开指数首版使用已保存的响应证据，不自动取数；真实账户验收仍需完整原件、准确时点和五交易日对照。

**政策对照的限度**：在同一个真实账户上逐日评估多个政策，只能比较建议差异、约束违例与证据缺口，不能比较收益。比较收益需要每个政策各自的模拟账户轨迹（冻结成交、费用与不可交易处理），与 v1 一起设计，样本单位与采用条件写进[判断验证方案](judgment-validation.md)。

## 7 风险防线与守则

- **账户数据安全**：唯一触碰真钱数据的部分；以只进不退（Append-only）事件簿、作废式冲正（void）、截图证据哈希强绑定与原库只读存档保护；
- **投资策略连续性**：`policy/v0` 完整继承原规则与风险参数，激活机制显式可审计；
