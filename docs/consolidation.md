## 1 为什么合一

三仓结构来自“多个消费者共用一个库”的设想，这个设想没有发生，代价都落在接缝上：

- 两个数据库：判断与交易对不上。2026-11-11 实测 25 笔买卖 0 笔关联报告；其中 20 笔发生在首份报告（10-21）之前，5 笔可按成交日机械推导，没有一笔需要人工确认。
- 两套研究流程：宿主 Agent 在 Skill 里得出的公司结论不经引文与计算核验，也不进判断账本。
- 两套指标：PE 分位一端是近 5 年日频 `pe_ttm` 分位值，另一端是默认 10 年、收盘价除以年报 EPS 的百分位。
- 一套发版仪式：Lib 每次发版打 wheel、锁哈希、两端回归，而 Research 只用它 3 个符号。
- Skills 的测试（2.2 万行）与说明文字（7700 行）多于运行代码（1.7 万行），账户库只有 37 条事件、10 条持仓。

## 2 不变量与所有者决定

只保留三条不变量，其余都可以改：

1. **真钱只由所有者动**。系统不下单；账户数据不丢、不错。
2. **冻结的判断不改写**。已冻结的预测、批次、记分规则与判断契约面不动；12-01 月批前契约面哈希保持不变。
3. **事实可溯源、计算经程序**。任何入口写入判断都过同一个核验。

另保留一个设计：研究 AI 看不到持仓和账户，防止迎合持仓。

所有者 2026-11-11 决定：

- **D1** 合并数据库，归档 Lib 与 Skills 两个仓库。
- **D2** 记账从逐次确认改为“对账通过即入账，对不上才问”。
- **D3** 现行投资规则原样作为政策 v0；此后换政策由所有者切一次指针。

本方案范围内的数据库迁移、compose 服务与挂载、Hermes 任务调整和宿主客户端安装随三项决定一并授权；每段验收向所有者报告新旧对照结果，对照不一致的段顺延，不带着差异切换。

## 3 目标结构

```
a_share_research/
├─ （现有模块）   研究、核验、估值、记分、网页、worker；不改名、不搬动
├─ core/          数据 Provider 与确定性计算（并入 Lib；交易成本、板块、行情校验）
├─ account/       账户事件、持仓、对账入账、业绩与交易归因
├─ policy/        政策版本；v0 为现行规则原样
├─ tools/         工具注册表、tools 进程、CLI 客户端
└─ gate.py        入账门
skill/a-share/    唯一的 Skill
ops/hermes/       定时脚本
```

**一个账本**。账户表进入同一个 SQLite。交易与报告的关联是视图 `trade_attribution`：同公司、成交日及之前、通过复核的最近一份报告；没有则为“无研究依据”，成交早于首份报告的另标“上线前”；同日报告单独标记。事件上显式填写的 `report_id` 优先于推导。关联不是要维护的状态，不需要写入和确认。

**一份工具注册表，三种出口**。研究工具沿用现有 `TOOLS` 定义注册，不重写；账户与政策函数注册为新工具。

| 出口 | 用途 | 说明 |
|---|---|---|
| worker 进程内 | 研究 AI | 只见研究范围 |
| `tools` 进程 | 宿主 Agent、Hermes | 同一镜像的第三个服务，只听 `127.0.0.1:8621`；持行情凭据，不持模型凭据；提供 `GET /tools`、`POST /tools/{name}` 与 MCP |
| `ashare` CLI | 不支持 MCP 的宿主、脚本、人 | 单文件、只用标准库的客户端，调 `tools` 进程；宿主上不再维护 Python 运行环境 |

| 范围 | 工具 | 可用方 |
|---|---|---|
| research | 现有 12 个研究工具、报告与论点卡读取、外部研究的开启与提交 | 研究 AI、宿主 Agent |
| account | 持仓、成交入账、对账、账户快照、业绩、交易归因 | 宿主 Agent、Hermes |
| policy | 政策评估、仓位、情景比较、L3/预警/Tier 状态 | 宿主 Agent、Hermes |
| owner | 政策生效切换、API Key 管理 | 所有者登录后的网页或本地命令 |

API Key 带范围；web 进程仍不持模型与行情凭据。

**入账门**。`gate.submit(run, draft)` 复用现有机械检查与独立复核：机械检查同步返回逐条问题，独立复核由 worker 排队执行，通过后才成为报告。宿主 Agent 用 research 工具取证（材料记入一次 `external` 运行），提交后与 worker 的判断同等入账。报告记录生产者（`worker` 或 `external:<Key 名>`），记分按生产者与判断契约分组。

**政策即版本**。政策是实现同一接口 `evaluate(账户状态, 行情, 论点卡) → 动作、复核项、仓位` 的模块，不是规则引擎或 DSL。

- v0 把现行 runtime 搬入 `policy/v0/`，输出沿用 `monitor-v1`；凡结构化输出中影响动作的字段全部保留。只存在于 Skill 文本、由宿主 Agent 执行的步骤原样移入 `policy/v0/guide/`，默认保留，删除须有影子周对照依据。
- v0 的输入口径冻结（含 10 年静态 PE 百分位）；口径统一通过新政策版本进行。
- 生效指针 `policy_activations` 只追加，只能在 owner 范围内切换。已注册的政策每日都在同一账户状态上评估并保存结果，供记分对照。

**对账入账**（D2）。输入是券商截图或交割单抽取的成交行与账户快照，连同证据文件哈希。程序检查：逐只股票“期初 + 买 − 卖 ± 送转 = 快照股数”；现金变动与成交净额、分红、费用一致；持仓市值 + 现金与总资产之差在容差内。通过即追加事件；不通过返回逐项差异，Agent 只就差异问所有者。事件只追加，更正用补偿事件。容差在影子周用真实截图实测后写入 v0 参数（11-28）。

分析状态（L3、预警、Tier、论点版本、分析结论）由 Agent 经 policy 工具直接追加，带证据与版本，不再逐次确认。这一条超出 D2 的字面范围，所有者不同意时改回逐次确认。

**一个 Skill**。`skill/a-share/SKILL.md` 只做路由：工具从 `GET /tools` 或 MCP 发现，三条不变量，按场景加载 `policy/v0/guide/` 的资料。QA Skill 及其 rubric 删除：报告质量由入账门负责。

**Hermes** 仍只管定时与送达。持仓代码同步不再需要；`a-stock-*` 任务与 crontab 的持仓检查在切换时改调 `ashare`，时间与通知数量不变，周日记分推送增加交易归因一段。

## 6 过渡期规则

- 功能改动只在本仓库进行；Lib 与 Skills 两仓只接受生产故障修复，修复同步到本仓库对应子包。
- 切换前旧 Skills 的写入门禁（`--confirm-write`）与现行流程照常生效；本文件描述的新规则自各段发布后对新代码生效。
- 现有 Research 模块不为目录整齐而改名或搬动；契约面清单内的源码在 12-01 月批前不改。
- 并入的代码沿用本仓库的[工程约束](../AGENTS.md#工程约束)与[数据层治理](data-foundation.md#7-验收与治理规则)；镜像表原样复制并补 `company_key`。

## 7 回退与文档收敛

**回退**。第 1–3 段新代码只读账户数据，回退即发布工具回退镜像；迁移为加法，旧镜像不读新表。切换后回退：停用新写入标志，重新安装旧 Skills 指向原 `cache.db`；切换后已入账的新事件先由 `ashare` 导出，再按旧命令补记。两个旧仓库归档而不删除。

**文档**。切换后收敛为：`AGENTS.md`（不变量与授权）、`ARCHITECTURE.md`（一页，取代项目契约与产品方案的架构章节）、`PRODUCT.md`、`DESIGN.md`、`README.md`、实施计划（状态与部署），以及各实验规格（它们定义记分口径，保留）。项目契约、本文件和 Skills 侧的运行合同随之删除；全局 `~/.claude/CLAUDE.md` 中的 Skill 名称与持仓查询方式同批更新。

## 8 风险

- **账户数据迁移**。唯一触碰真钱数据的一步；用逐字段对照、历史事件重放和原库保留三层保护。
- **v0 行为意外改变**。影子周对不上就不切；v0 输入口径冻结。
- **账户数据进入网页所在的库**。此前 Research 刻意不存持仓；单用户且需登录，研究 AI 的隔离改由工具范围保证。
- **12-01 月批**。首个自动双组批次跑在合并后的代码上；用契约面哈希测试和 11-28 之后不发布来保护。
- **工期**。不确定性集中在搬运 Skills 运行时并逐字段对上 FIFO、分红与送转；这部分顺延时只影响第 3、4 段，不影响月批。
