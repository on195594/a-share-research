# Web 与 MCP 双入口平台方案

手机 Web 与外部 Agent 共用研究、账户与政策服务。同一业务产生同一份数据与回执，便于从账户扣费后表现追溯到研究和成交。现行进程边界见[系统架构](../ARCHITECTURE.md)，接入方式见 [README](../README.md#web-与-mcp-接入)。

## 双入口与身份

Web 负责本人 GitHub 登录、OAuth 授权及阅读页面。tools 通过原生 HTTP MCP 公开工具注册表，按 grant 和账户开关发现与调用。账户表单经会话、同源与 CSRF 校验，以 Web 专属 grant 调用内网 MCP。页面读取可直接使用共享视图。分开部署使慢采集不会占满页面请求名额，也保留各自的发布排空边界。模型凭据只交给 worker；worker 和 tools 分别持有所需的行情凭据。

每个宿主或脚本使用独立 grant，外部业务授权使用 assistant 角色，本机 owner 凭据用于政策管理。网页客户端预注册回调地址，通过授权码与 PKCE S256 取得绑定到本站 `/mcp` 的访问令牌。刷新令牌保留 grant 身份；撤销保留审计编号，同时使续签、调用和写事务内授权失效。CLI 与 Hermes 使用 PAT。公网 MCP 校验 Host、Origin（若提供）与 Bearer 凭据，无需建立持久会话。

服务端优先返回结论、时点、缺口与原记录链接。成功的 MCP 结果同时有文本和结构化数据；参数错误指出字段路径。研究提交返回任务编号与进度页，客户端可按原身份和请求编号找回任务。凭据失效时刷新或重新授权，发布暂停或名额已满时用原请求稍后重试，超时或断线时先查回执。各宿主工作流共用仓库发布的 [a-share Skill](../skill/a-share/SKILL.md)。

### 4.3 打通研究、账户与政策数据

公司总览（`research_company_overview`）按公司关联研究与公告，按绑定账户和当前持仓周期读取股数、成本及在仓论点，避免把已清仓周期的判断挂到新持仓。组合总览（`account_portfolio_overview`）从已核实持仓出发，也列出缺少研究的公司。两端读取已存监控评估、公告复核状态和区间净值凭证，注明政策身份、时点和缺口。成交明确采用的研究与成交当时可查的研究分别展示。

Hermes 与 Web 共用扫描事件的 ID 和处理状态，网页显示未闭环项，推送只投递符合冷却与去重条件的变化。扫描范围和复核判据见[顾问闭环方案](investment-advisor.md#7-a4-窄范围主动复核research-扫描--hermes-调度)。

Web 可上传多份凭证，单笔记账表单列出当前版本、持仓与最近凭证，显示现金和市值的对账差额。Agent 可按上传时间查取证据引用。账户流水对账后追加，纠错以作废事件及替代流水留痕；资产观察仅记录观察值。周期分析以版本号追加修订；政策评估保留原身份与输入。区间净值使用可追溯的估值、资金流声明与 H00906 收盘证据，省略指数凭证时由服务端采集。两端均可凭回执回看原结果。

## 5. 实施分段

旧 `/tools` 业务 REST、`/api` Agent JSON 和 `agent:` 会话在段 4a 前保持热备。现行 worker 的研究模型看不到持仓，单股和月批都只接收研究材料。2026-11-29 至 12-04 首个月批冻结窗口内暂停全部发布。固定日期和回退基线分别见[固定里程碑](implementation-plan.md#固定里程碑)与[当前部署](implementation-plan.md#当前部署)。

**4a · 退役旧入口（2026-12-18）。** 公网 MCP 稳定满一周后，核对 web 与 tools 日志中的旧路径调用及旧 research key #1、#3 的使用记录。仍有调用就列出调用方、顺延一周。无残留才移除上述业务路由和会话、撤销两枚旧 key、同步接入文档；保留网页、OAuth、上传和发布就绪检查。应用回退目标为上一个生产镜像（库版本相同），撤销记录保留，见[回退](../README.md#回退)。v24 镜像无法读取 v25 库。

**4b · 按请求带入持仓（2026-12-23，契约号递增）。** 12-04 月批验收后、冻结窗口外实施。单股请求拟支持 `holdings_context`，省略与 `false` 等价。日常仓位解读由外部 Agent 结合报告与账户完成；需要沿买入理由寻找反证时，调用者可选择让研究员读取快照。设计与验收遵循以下约定。

1. 受理知仓请求时，在创建任务的同一事务冻结目标公司的股数、成本、买入日、持有期、政策评估引用及周期论点版本。权重须有当时的价格与已核实的分母；经核实未持有和无法核实分别记录。调用者意图与服务端快照分开保存。
2. 相同请求编号按规范化意图比较。问题或输入模式不同则报冲突，意图相同则返回原任务与原快照。重试、复核与重放沿用快照，调仓后要看新状态须发新请求。
3. 快照随材料纳入哈希。持仓字段与实际渲染进入判断契约面，探索、成文、复核、修正看到同一份输入，模型的工具白名单保持只读研究能力。在仓论点用于引导反证取证，持仓成本不能用来推定企业价值或等待价。
4. 盲研究在选材时排除知仓报告及其可传播内容，覆盖报告复用、显式父报告、自动前序、纠错和方法目录。父报告上下文只投影公开字段。普通请求的盲模式指服务没有注入快照；正式盲月批使用系统问题和受控材料。
5. 程序在报告、卡片和精简输出中标明输入模式与快照摘要。公司页并列两种报告，默认卡片、扫描通知和建仓判断仍使用盲报告。超额、立场、预测、议程、区间、扫描归因和稳定性先按“契约 × 输入模式”分组，再取各组首样本。同一月批只用一个契约。

4b 按 D 类验证，未通过则顺延至 2027-01 月批验收后（01-11），避开 12-30 至 01-04 冻结窗口。应用回退目标为上一个生产镜像，若 4b 带迁移则先恢复发布前备份（见[回退](../README.md#回退)）；知仓契约报告需用理解新分组的版本记分。是否扩大知仓研究的使用范围，看它能否更早发现反证、减少左尾损失并被实际决策采用。

## 6. 验收

- Web 与 Gemini 对同一组凭证走通上传、对账入账、扣费后净值对照 H00906。调用者无需手工复制哈希或准备指数行情；资料不齐时两端指出同一缺口。同一时点的组合待办与依据一致。
- Gemini 与 Claude.ai 由所有者本人从未登录状态完成 OAuth 授权，核对实际协议版本、调用、丢响应后查回、刷新与撤销。客户端支持情况按实测记录，待验项见[实施计划](implementation-plan.md)。
- 4b 需用同一公司并列验证知仓与盲研究、同号重试快照不变，以及记分分组正确。先产生知仓报告与纠错，再跑同公司月批，查最终排序输入中有无知仓内容。新旧契约按[同材料稳定性测量](judgment-validation.md#同材料稳定性测量)对照。
