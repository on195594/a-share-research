# AI 核心能力演进路线图

更新：2026-10-22。职责见[项目契约](project-contract.md)，交付步骤见[实施计划](implementation-plan.md)。阶段按需求和验收结果推进，不预设模型发布时间或固定工期。

## 1. 目标场景

用户问“这次财报是否改变了我对这家公司的判断”：Agent 读取已有报告和原文，只补与结论有关的新证据，解释哪些判断发生变化；涉及已有持仓时，再调用当前账户风险快照。研究材料、公司判断、账户动作分别保留来源和状态。

长期积累三种资产：可追溯证据、稳定领域工具、真实反馈形成的评估案例。AI 逐步承担假设提出、反证搜索和取证顺序选择；计算、状态和授权仍由可验证程序执行。

## 3. 分阶段路线

| 阶段 | 交付能力 | 进入条件 | 退出标准 | 当前状态 |
|---|---|---|---|---|
| R0 职责对齐 | 单一项目契约、路线图、实施计划及三个仓库入口 | 本次用户文档请求 | 依赖与 owner 表述一致；规划能力明确标识；链接和差异检查通过 | 文档已更新、本地已验证；Claude 复核通过；提交及发布见各仓 Git 记录 |
| R1 版本身份与评价基线 | Research 研究结果及 Skills 评估候选的身份可追溯，能比较当前质量 | 现有系统继续维护与升级 | 上述结果的材料、代码、模型、规则及评估记录可关联；基线如实保留已知错误和未验证项 | Research worker 已部署并通过线上验收；首次基线已冻结，含已知缺陷 |
| R2 研究证据复用 | Agent 按需只读消费报告与引文 | 出现具体会话复用需求或重复取证成本，且有首个消费者 | 一个真实问题从已有报告到原文回答贯通；过期、错公司、缺证据等被正确处理 | 需求触发后实施 |
| R3 有界自主取证 | 宿主 Agent 针对证据缺口选择工具、寻找反证 | 固定流程存在重复失败且工具探索有可测收益 | 同材料对比改善目标案例；工具、停止和写入边界通过；无已知质量回退 | 后续候选 |
| R4 持续研究闭环 | 新信息触发受影响判断的复核，人工修正进入评估 | 持续复核需求成立，触发方式和运行范围明确 | 能解释新增证据、受影响判断和复核结果；重复触发不重复产生副作用 | 远期候选 |

R2–R4 不构成默认任务队列，进入条件分别判断；实施计划中的依赖只指必要技术前置。只读复用不必等待模型比较完成，手动复核不依赖自主取证。阶段可以暂停在已满足需求的位置；金融股等产品需求可独立排期，不必等待整个路线完成。

R1 不承诺为 Skills 所有日常产物新增模型或宿主身份字段；当前范围是评估候选的可追溯性。R0 的本地文档交付与三仓远端发布分别记录，远端链接需相应文档发布后才能在线使用。

## 4. 模型进步如何转化为系统能力

1. **推理能力更强**：在相同真实材料上比较模型，删除已无收益的提示词补丁或流程步骤。每次只改变可归因的因素，保留机械核验和范围约束。
2. **工具使用更可靠**：先让现有宿主 Agent 使用明确的报告读取、引文定位和风险快照能力；模型只对未解决的关键缺口展开。Research worker 的无工具调用约束保持，直接改变它需要另行明确设计范围。
3. **上下文与文档理解增强**：按任务取得原文和结构化事实，保留论断到来源的定位。是否改用直接 PDF/多模态理解，由真实文档对比决定，不预先增加解析链或检索基础设施。
4. **长任务能力增强**：先验证任务确实跨越当前运行边界，再考虑阶段结果保存和恢复。只有长任务中断已成为实际成本，才升级现有失败重跑机制。
5. **反馈持续积累**：用户指出的错误进入脱敏评估样本；模型或规则候选经过回放、检查和人工复核后采用。投资规则的生效继续服从既有授权，不从单次收益或一份好报告推导有效性。

这些是基于现有工程实践的规划判断，不是对未来模型的能力保证。可参考：[workflow 与 agent 的任务分工](https://www.anthropic.com/research/building-effective-agents)、[模型执行、工具与持久状态的分离](https://www.anthropic.com/research/managed-agents)、[Agent 评估实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。

## 5. 衡量进展

| 维度 | 观察内容 | 使用方式 |
|---|---|---|
| 证据质量 | 关键论断支持、期间/主体/单位正确、重要反证遗漏 | 程序检查与人工抽查分开记录；已知关键事实错误阻断采用 |
| 决策可靠性 | 缺失/过期/冲突处理、状态一致性、W1 边界、多轮追问稳定性 | 当前候选必须通过适用行为案例；历史捕获只说明历史行为 |
| 任务效果 | 报告完成、回答原问题、范围外正确拒绝、失败原因可理解 | 保留现有验收底线，并与同材料基线比较；不以降低门槛掩盖回退 |
| 使用成本 | 耗时、调用次数、人工修正与重复取证 | 比较新增复杂度是否有实际收益；费用仅作观测，不新增成本审批 |
| 升级效率 | 新模型/Skill 从评估到可采用的验证工作量 | 使用稳定案例和运行身份比较，保留可回退版本 |

投资表现单独按时间、现金流、市场基准和实际决策背景复盘；工程质量指标不直接证明 AI 带来超额收益。历史研究评估使用当时已公开的材料，最新修订数据不能冒充时点数据。

## 6. 排期与停止条件

R1 首批交付及 Research worker 部署已完成；下一步处理已记录的指标缺口、评价与参数绑定缺陷。R2 的首个场景是“读取已有报告回答问题”，仍需具体消费者需求，先定义最小只读合同；宿主确实需要时才增加 MCP 适配，不恢复旧 Tracker 接口。

[研究方案的产品候选](proposal.md)仍按需求排序：金融股有既有未满足需求记录；报告读取需要真实消费者；初筛继续后置。金融股支持需要对应财务口径和独立评估子集，不能仅因为 Lib 存在银行框架而视为已支持。

本路线保留三个仓库、现有数据库和运行时，不预设新编排平台、向量库、事件总线、多 Agent 流水线或自动交易。新增依赖和架构层只有在现有结构无法满足已确认需求时才评估；每阶段达标后停止扩展。
