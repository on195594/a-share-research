# AI 核心能力演进路线图

更新：2026-11-13。目标结构见[合一重构方案](consolidation.md)，工作包状态与部署见[实施计划](implementation-plan.md)。阶段给固定日期和到期默认动作，不设“等条件成立再做”；改日期直接改第 3 节并写原因。

## 1. 目标场景

**北极星是赚钱**（2026-10-31 所有者确认）：账户扣费后跑赢全收益基准。研究深度、初筛与工程质量都服务于它；判断必须可记分，优势假设必须可证伪，见[判断验证方案](judgment-validation.md)。

用户问“这次财报是否改变了我对这家公司的判断”：Agent 读取已有报告和原文，只补与结论有关的新证据，解释哪些判断发生变化；涉及已有持仓时，再调用当前账户风险快照。研究材料、公司判断、账户动作分别保留来源和状态。

项目积累的是可记分的判断账本，知识检索只是读取面（[积累方案](research-accumulation.md#定位可记分的判断账本2026-11-05-所有者确认)）。

## 2. 演进原则

模型会持续变强，系统各部分的价值走向相反。长期投入左列，右列保持薄：

| 随模型升级增值 | 随模型升级贬值 |
|---|---|
| 可溯源的证据与时点数据 | 提示词里的步骤与禁令 |
| 受控工具与可操作的报错 | 固定流程、路由与阶段划分 |
| 判断账本、冻结样本与记分规则 | 运行上限的具体数值 |
| 权限与状态边界、机器合同 | Skill 文本和为旧模型缺陷加的补丁 |

1. **一个判断来源，一本账**。公司判断只经同一个入账门进入判断账本。网页、API、宿主 Agent 和未来模型使用同一套证据与核验，按生产者身份（模型、判断契约、入口）分组记分，才能比较谁的判断更赚钱。
2. **AI 提议，程序核验，人授权**。AI 自主决定取证、假设与论证；事实可溯源、计算经核验、运行隔离三条硬边界不随模型能力放宽（[AGENTS](../AGENTS.md#ai-自主权与三条硬边界)）；账户动作与生效政策由所有者决定。
3. **用记分决定去留**。A—F 框架、三档结论、估值方法、新模型和新脚手架都是待检验的假设，按[判断记分](judgment-validation.md#4-判断记分)采用或退役，不因存在已久而保留。
4. **换模型先做减法**。切换模型或进入契约窗口时，评估集同时跑现行版本与删减候选（去掉为旧模型加的提示段、流程步骤与上限）；删减版不差就采用。
5. **接缝走机器合同**。跨项目只经版本化接口和结构化字段，不从自然语言反推状态；能由程序检查的约束写进工具与合同，不写进提示词。

## 4. 反馈如何转化为能力

纠错关联原报告及具体位置，触发新的核查任务；原报告保留。AI 用证据判断反馈是否成立，解释原因，并提出数据、计算、提示词或方法的最小修正建议。已通过核查的纠错可将方法与适用边界保存在原报告 JSON 中，后续按问题跨公司检索；方法引用和检索记录保留（召回不等于实际采用），当前公司事实仍须重新取证。针对方法条目的后续核查可替换或撤下旧检索项，失败核查不生效，原报告不改写；不能把用户意见或方法当新事实。

真正的改进沿用开发闭环：真实失败 → 定位根因 → 小候选差异 → 相关真实案例与正常案例 → 采用或保留拒绝原因。候选可删规则，不默认增加提示禁令；无需新状态机、优化平台或每次重跑全部验证。代码和生效政策不由研究模型直接改写。工程正确性与投资效果分别衡量；新工作包立项写明服务的赚钱环节和预期改善的记分，否则标为维护或故障修复（[判断验证方案第 2 节](judgment-validation.md#2-北极星与工程纪律)）。

K7 已于 2026-11-10 退役，保留历史数据只读与纠错方法检索，依据见[退役说明](research-accumulation.md#6-k7-已退役2026-11-10)。

## 5. 衡量进展

| 维度 | 观察内容 | 使用方式 |
|---|---|---|
| 投资表现（最终衡量） | 预测命中率对比朴素基线、相对判断的汇总超额与左尾、关联交易相对基准的结果 | 按[判断验证方案](judgment-validation.md#4-判断记分)前瞻记分；历史评估只用当时已公开的材料 |
| 证据质量 | 关键论断支持、期间/主体/单位正确、重要反证遗漏 | 程序检查与人工抽查分开记录；已知关键事实错误阻断采用 |
| 决策可靠性 | 缺失/过期/冲突处理、状态一致性、W1 边界、多轮追问稳定性 | 当前候选必须通过适用行为案例 |
| 任务效果 | 报告完成、回答原问题、范围外正确拒绝、失败原因可理解 | 与同材料基线比较；不以降低门槛掩盖回退 |
| 升级效率 | 新模型从评估到采用的工作量、每次升级删掉了多少脚手架 | 用稳定案例和运行身份比较，保留可回退版本 |

耗时、调用次数与费用只作观测，不设成本审批。工程质量指标不直接证明 AI 带来超额收益。

## 6. 不做

不增加向量库、独立知识库、事件总线、多 Agent 流水线或自动交易；不让研究模型改写代码、校验器或生效政策。接口能真实提交并读到可核查结果、追问与纠错可用即停止扩展接口。
