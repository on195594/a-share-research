# AI 核心能力演进路线图

## 1. 目标场景

一家公司发布新财报时，研究员用原报告和新增证据回答哪些判断需要修订，保留原预测供日后记分。涉及持仓时，账户助手结合研究结论、账本和生效政策给出复核事项。最终衡量的是账户扣费后相对全收益基准的表现。见[产品目标](../PRODUCT.md#目标与成功标准)与[判断验证方案](judgment-validation.md)。

## 2. 演进原则

| 长期投入 | 随模型升级重新评估 |
|---|---|
| 可溯源的证据与时点数据 | 提示词中的步骤与禁令 |
| 受控工具与可操作的报错 | 固定流程、路由与阶段划分 |
| 判断账本、冻结样本与记分规则 | 探索轮数与调用上限 |
| 权限、状态归属与版本化接口 | Skill 文本和针对特定模型的补丁 |

各入口共用证据、核验与判断账本，按模型、判断契约和入口分组记分。AI 可以提出假设和替代方法，程序负责核验，研究权限见[研究方案第 3 节](proposal.md#3-研究-ai-的自主权与边界)，账户操作由所有者决定。

框架、结论档位和估值方法按前瞻记分决定去留。切换模型或删减判断契约时，用同一评估集比较现行版本与删减候选。去掉提示段、流程或上限后表现相当，就采用更简单的版本。接口用结构化字段表达版本、状态与错误，能由程序核验的约束放在工具中。这些原则按变化速度落成三层：事实与规则、worker 的作业编排与研究工具、可整层替换的 agent-runner，见[分层重构](agent-architecture.md#2-分层与取舍)。

## 3. 阶段

| 环节 | 现有能力 | 尚待解决的缺口 |
|---|---|---|
| 形成公司判断 | 基本面与同业研究、接续报告、估值情景与可兑现的检查点 | 银行、保险和券商需要独立的财务口径与评估样本；需求值得扩展时，先建专用财务表和每类两家公司的评估子集。 |
| 检验选股与判断 | 月批冻结候选与排序，按契约跟踪预测、超额和左尾 | 等待前瞻样本成熟，分别检验初筛规则和研究判断。模型或提示词的效果需隔离变量比较。 |
| 关联研究与账户 | 绑定账本保存成交显式依据，也可查询成交时可用的报告 | 用有显式依据的成交检验研究对决策的贡献。比较不同政策的收益需要各自的模拟账户轨迹。 |
| 统一计算口径 | 研究与政策共用数据层，v0 保留自身指标定义 | 核对分位、TTM 与复权口径的差异，口径变动进入新政策版本。 |
| 接入与送达 | Web 与 MCP 共用业务数据，Hermes 调度并通知 | 核对网页客户端 OAuth、真实账户流程和定时通知送达。按请求带入持仓的研究须与盲研究分组。见[双入口方案](web-mcp-platform.md)。 |

各阶段的到期日期与到期动作见[固定里程碑](implementation-plan.md#固定里程碑)。

## 4. 反馈如何转化为能力

纠错指向原报告和具体位置，另行核查并保存结论。经核查的方法可跨公司检索，需记录适用条件，当前公司的事实仍回到原始证据。方法来源和检索口径见[研究产品方案](proposal.md)。

开发改进从真实失败出发，定位到数据、计算、提示词或方法，提出最小改动，再用相关案例和正常案例决定是否采用。评估保留失败原因。这个过程借鉴了 Open Deep Research 的按问题补证、RD-Agent 的假设检验和 GEPA 的失败案例对照。OpenBB 的多入口共用数据与 Hermes 的经验复用用于设计接口和方法检索。

## 5. 不做

判断账本以现有证据、报告和检索为基础。项目不另建独立知识库、向量库、事件总线或多 Agent 流水线，不提供自动交易。
