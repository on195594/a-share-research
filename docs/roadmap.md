# AI 核心能力演进路线图

更新：2026-10-31。职责见[项目契约](project-contract.md)，交付步骤见[实施计划](implementation-plan.md)。阶段按需求和验收结果推进，不预设模型发布时间或固定工期。

## 1. 目标场景

**北极星是赚钱**（2026-10-31 所有者确认）：账户扣费后跑赢全收益基准。研究深度、初筛与工程质量都服务于它；判断必须可记分，优势假设必须可证伪，见[判断验证方案](judgment-validation.md)。

用户问“这次财报是否改变了我对这家公司的判断”：Agent 读取已有报告和原文，只补与结论有关的新证据，解释哪些判断发生变化；涉及已有持仓时，再调用当前账户风险快照。研究材料、公司判断、账户动作分别保留来源和状态。

长期积累三种资产：可追溯证据、稳定领域工具、真实反馈形成的评估案例。AI 逐步承担假设提出、反证搜索和取证顺序选择；计算、状态和授权仍由可验证程序执行。

## 4. 反馈如何转化为能力

纠错关联原报告及具体位置，触发新的核查任务；原报告保留。AI 用证据判断反馈是否成立，解释原因，并提出数据、计算、提示词或方法的最小修正建议。已通过核查的纠错可将方法与适用边界保存在原报告 JSON 中，后续按问题跨公司检索；方法引用和使用记录保留，当前公司事实仍须重新取证。针对方法条目的后续核查可替换或撤下旧检索项，失败核查不生效，原报告不改写；不能把用户意见或方法当新事实。

真正的改进沿用开发闭环：真实失败 → 定位根因 → 小候选差异 → 相关真实案例与正常案例 → 采用或保留拒绝原因。候选可删规则，不默认增加提示禁令；无需新状态机、优化平台或每次重跑全部验证。代码和生效政策不由研究模型直接改写，正常开发及发布仍遵守原有授权。工程正确性与投资效果分别衡量；新工作包立项写明服务的赚钱环节和预期改善的记分，否则标为维护或故障修复（[判断验证方案第 2 节](judgment-validation.md#2-北极星与工程纪律)）。

## 5. 衡量进展

| 维度 | 观察内容 | 使用方式 |
|---|---|---|
| 证据质量 | 关键论断支持、期间/主体/单位正确、重要反证遗漏 | 程序检查与人工抽查分开记录；已知关键事实错误阻断采用 |
| 决策可靠性 | 缺失/过期/冲突处理、状态一致性、W1 边界、多轮追问稳定性 | 当前候选必须通过适用行为案例；历史捕获只说明历史行为 |
| 任务效果 | 报告完成、回答原问题、范围外正确拒绝、失败原因可理解 | 保留现有验收底线，并与同材料基线比较；不以降低门槛掩盖回退 |
| 使用成本 | 耗时、调用次数、人工修正与重复取证 | 比较新增复杂度是否有实际收益；费用仅作观测，不新增成本审批 |
| 升级效率 | 新模型/Skill 从评估到可采用的验证工作量 | 使用稳定案例和运行身份比较，保留可回退版本 |

投资表现是最终衡量，按[判断验证方案](judgment-validation.md#4-判断记分)前瞻记分：预测命中率对比朴素基线、相对判断的汇总超额与左尾；工程质量指标不直接证明 AI 带来超额收益。历史研究评估使用当时已公开的材料，最新修订数据不能冒充时点数据。

## 6. 排期与停止条件

R3 的验证记录见实施计划（`git show 52d1eec:docs/implementation-plan.md`「R3 推进记录」）；批次 E 的阶段与验收见[方案第 7 节](screening-experiment.md#7-分阶段)。

接口能真实提交并读到可核查结果、追问与纠错可用、研究验收通过即停止扩展。批次 E 按方案分阶段推进。金融股仍须对应财务口径和评估子集；不增加向量库、独立知识库、事件总线、多 Agent 流水线或自动交易。
