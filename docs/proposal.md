# 研究产品方案

产品的用户、使用路径与成功标准见 [PRODUCT.md](../PRODUCT.md)。本方案说明如何把披露、财务数据和研究问题变成可复核的判断。账户、政策与研究服务的职责见[系统架构](../ARCHITECTURE.md)。

## 2 从用户角度的取舍

Web 和 MCP 受理同一种研究请求。从网页提交没有附加问题的研究时，若当天已有报告，先提供阅读入口。用户可以提交具体问题。追问与定位纠错另存关联原报告的新任务。初筛只在批次开始时冻结全市场集合，单股研究按问题取证。

首屏给出研究价值判断、理由和最强反证。报告区分研究价值、行动立场和短期价格参考。价格参考按需由程序计算，有效期过后隐藏价位。候选组合按独立的[实验规则](screening-experiment.md)入场与退出。

复核失败时不展示判断。仅当最后一稿通过机械检查、完成语义复核，且每个问题都能定位到该稿时，才展示未受影响的有出处事实。部分问题尚未答完时的交付条件见[跨轮复核](#51-统一来源与跨轮复核)。

## 4 数据与模型

- 财务与行情数字优先从 TuShare 生成带期间、单位的表行。业务、风险及对管理层解释的核查回到披露原文。三表、经营序列和同业快照的可比口径见[基本面方案](investment-upgrade.md)。
- 基础材料预载年报的管理层讨论与分析。按境外格式编制且没有该节的年报，取业务概览至财务概览；无法定位就记缺口，研究员可检索和读取原文。申通同材料对照中，预载使取证轮次从 20 轮降至 13 轮，故保留这一入口和现有版面规则。
- 有更新的半年报或季报时优先核对。临时公告先查标题，再取相关 PDF；同时保存查询范围、关键词及截断情况。只有实际读取的页文可以作为引文，业绩预告、中标公告与已确认的利润、收入分别解释。
- 作者与复核者分别通过 pi 调用，可配置不同模型，按实际身份保存调用记录。两者使用同一份证据，复核着重检验论断、因果和重大遗漏。

## 5 研究流程

worker 在采集前冻结模型配置与本次调用上限，保存基础材料后为这次研究启动一个 agent-runner。研究员通过本次任务的 MCP 工具自主选择补读披露、查同业、调用计算或提交稿件。worker 执行工具并保存出处。测算用的假设输入带说明与单位，和事实输入分开，沿计算链保存。正文中的派生值可引用计算行，仅由假设支撑的数字须在同句说明条件。情景与回报的口径见[顾问方案](investment-advisor.md)。

探索与修正共享同一份材料、工具缓存与取证额度。worker 返回本次调用是否改变证据集合。runner 按整轮判断增量，连续两轮没有新增来源、页文、计算或方法就收起取证工具，预留成文与复核调用。计算只换用途名称、查询返回同页，都按同一份证据处理。成功请求复用结果，失败请求在证据或可引用行变化后可再执行。运行时限、调用与修补上限及其依据见[模型配置档](../a_share_research/model_profile.json)。

worker 对提交的整稿做机械检查，通过后 runner 启动独立复核。需要修正时，修补员从索引化原稿、问题、材料和程序估值开始新对话，可在剩余额度内补证或重算，并提交按章节与序号定位的补丁。程序原子合并，保留未涉及条目。非法补丁可在同一轮退回整稿重写一次。修补员可用问题 ID 和出处反驳批评。每次修正后重新检查并复核，当前配置最多修正两次。重放只使用冻结材料，交付前核对最终材料与来源快照的哈希。

### 5.1 统一来源与跨轮复核

所有阶段从同一张来源表读取主体、期间、公告日、URL、哈希及已读页。补证前核对同一来源的身份和页文，遇到冲突停止成文。工具返回后同步持久化材料快照与身份哈希。历史材料可以合并本报告保存的身份与页码；仅有页码时只提供 PDF 入口。

机器核对引文的来源、实际页窗及连续原文，并检查表行、单位、符号和计算输入。合法的同业、跨期或跨页引用保留实际主体、期间与页范围。问题自设的阈值按带符号数值、单位和比较语境逐处识别；同值的财务事实另须举证。独立复核检查这些数字能否支持所写的结论。

每轮复核绑定草稿与材料哈希。程序为新问题分配稳定 ID，独立复核者逐项决定维持、解决或有据驳回；修正者不能自行关闭。解决重大遗漏须指出新版位置与证据，改写、合并或删除原风险须说明依据和去向。格式无效时，复核者收到具体原因并可当轮纠正一次。原问题、绑定的草稿和历次决议保存在复核账本。补证、改写或在缺口栏写“未知”都不会自动关闭问题。

最后一稿完成复核后，若只剩有 ID 的未答完问题（`question`），位置为 `answer[i]`、`prior_status[i]`、`valuation`、`gaps[i]` 或 `missing`，可以交付。问题在账本中保持未解决，报告用 `open_questions` 与缺口逐项列明。论断错误、重大遗漏、其他位置的未解决问题及机械检查失败均阻断判断交付。失败结果标明阶段、具体问题和可采取的下一步。

## 研究方法库

方法卡帮助研究员选择取证角度，包括周期利润正常化、盈利质量与现金转化、自由现金流估值、增长与资本回报、价格隐含预期。每张卡在共享 Wiki 维护适用条件、公开来源、实际核对范围、所需证据和可检验的结论。实践推论单独标明。新增方法从研究遗漏或复盘发现出发，来源不足的留作草稿。[共享 Wiki 企业分析目录](https://github.com/on195594/wiki/tree/main/concepts/company-analysis)

非批次单股研究在开始时将有标题的 `stable` 卡与截至当时有效的历史纠错方法冻结到材料目录。批次只用截至批次边界的纠错方法，保持比较输入一致。卡片保存正文、来源链接与文件哈希，`methods_sha256` 绑定整份目录，复核与重放沿用快照。公司事实仍须引用本次材料中的披露或数据，方法卡没有可充当事实出处的行号。

`research_methods` 按空格分词，区分大小写，任一词命中正文即可，最多返回五条。仅在结果溢出且含卡时，将整项关键词命中或完整查询等于标题的卡稳定前置。MCP 检索当前 Wiki 稳定卡；Web 报告展示研究期间返回并记入 `methods_used` 的方法。三进程只读挂载同一目录，卡片正文由 Wiki 维护，工具的选择语义按[判断契约](judgment-validation.md#判断契约与修改规则)管理。

用茅台、卫星化学的三表样本核对，现有字段不足以拆分维持与增长资本开支，也不足以直接给出完整的企业或股权自由现金流。卡片可据此提示补读所需披露。

首批五份生产报告中四份调用了方法检索。缺少同材料无卡对照，方法卡对判断的增益仍待验证。真实案例核对一家受影响公司和一家普通公司，检查召回、复核及正文是否增添了足以改变结论、价格条件或反证的分析。只增加篇幅或套用模板的卡应删去，全部缺乏增量时移除挂载。2027-01-01 月批前的删减对照包括不挂载卡片。

## 6 状态与正确性

研究与价格任务状态为 `queued`、`running`、`done`、`failed`。服务先按请求者与请求编号查原任务，再查公司目录，同号不同内容报冲突。worker 重启时将带请求编号的普通中断任务重新排队一次，再次中断即失败；自动月批研究中断直接标记失败。CLI 自管的任务由原进程负责。

PDF 按内容哈希保存，页文本缓存绑定 PDF、提取器版本、模式和页文摘要；校验不符时重新提取，文件原子写入。报告正文哈希在发布时生成，报告与任务终态在同一事务提交。阅读直接使用已存报告和材料。备份前、恢复后或发生异常时，可用只读完整性巡检检查库、快照、引用及原件；缺少历史哈希的记录不补写。迁移与恢复见[数据层治理规则](data-foundation.md#7-验收与治理规则)。

## 11 后续候选

银行、保险、券商的财务表和风险披露口径与一般工商企业不同。若实际需求值得扩展，先建立专用财务表和每类两家公司的评估子集。现行受理按简称识别可辨认的金融公司，取证时再以财报公司类型检查范围。

## 报告语言治理（契约 2/4）

成文与修正先写经营状态或投资判断，再给出证据、影响和待验证事项。复核争辩留在审计，重大反证、假设条件和数据缺口保留在正文。四家公司同材料成文对照中，契约 4 的句尾规则将强否定词从每千字 10.7–15.5 个降至 0.9–3.8 个，结论档位、立场和风险条数保持一致。后续写作规则用相同回放对照检查可读性。
