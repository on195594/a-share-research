# 研究产品方案

2026-10-23 更新：保留 v3 首发记录；人与 Agent 共用的自主研究流程已实现、完成本地验收，并按用户本次授权部署上线，具体结果见实施计划。

a-stock-tracker 只作只读参考：可读它的代码、算法、提示词和历史记录，不依赖、不导入它的数据，也不改它。本方案维护产品范围、现有流程和首发历史；实现细节以代码为准。跨项目职责以[项目契约](project-contract.md)为入口，后续能力按[路线图](roadmap.md)和[实施计划](implementation-plan.md)的进入条件推进；生产版本与回退只维护在[当前部署](implementation-plan.md#当前部署)。

## 1 用户要做的事

用户是项目所有者和受其委托的 AI Agent，收盘后研究 A 股公司。已有能力：

1. **研究一家公司**：输入代码或名称，点一下开始，几分钟后读到一份报告：一句话结论（值得继续研究 / 需要谨慎 / 暂不值得，带关键数字）、最强反证、业务、财务，每个论断都能点开看原文出处和日期。
2. **回看研究过的公司**：公司列表，每家显示最新结论和研究日期，点进去读报告和历史报告。
3. **看价格参考**：读完报告后按需生成，由程序计算，不调用模型，显示依据日期和有效期，过期后隐藏价位。

本批已实现：提出具体研究问题，AI 自主补读最新披露、比较财务期间与同业、调用程序计算；读完可以追问和指出具体错误。网页与 JSON API 共用任务、材料与核验结果。“最新财报改变了什么”是首个验收场景，不是问题白名单。

不做：自动交易、仓位管理、收益承诺、多用户、独立笔记系统、关注列表、定时研究。

## 2 从用户角度的取舍

旧系统的使用记录（2026-10 线上）给出了依据：最近 20 次财报研究有 8 次“未能生成结论”；初筛 4 次全部失败；价格参考用过 7 次；所有研究都从网页提交，MCP 从未用于提交；“改变判断的条件”一段几乎每次都没形成；招商银行试了两次都因范围外被拒。

据此：

- **一键开始**。费用不再需要用户确认，不显示报价页和费用免责声明。同一家公司已有当天的报告时提示直接阅读；具体问题和追问直接创建任务。
- **失败也给用户东西**。复核没通过时，展示已通过机械核验的事实（每条带原文出处）和一句话失败原因，不展示未复核的结论。
- **提交前说清范围**。银行、保险、券商等金融股首发不支持，输入时就提示，不让用户等几分钟后才失败。
- **结论便于读，研究允许展开**。保留首屏三档结论和风险、业务、财务；具体问题另给带出处的回答和缺口。允许提出假设、反证及替代解释，派生数字经程序计算并保留输入和公式。
- **进度看得懂**。进度页显示当前步骤（取资料 / 成文 / 复核 / 修复）和已用时间。
- **首发范围**：财报研究 + 公司列表 + 价格参考。初筛、MCP 只读查询、金融股放在上线之后，按实际需要再做。

## 3 架构

一个 Python 包、一个 SQLite 文件、一个 PDF 目录、两个进程。

| 进程 | 做什么 | 持有 |
|---|---|---|
| web | FastAPI + Jinja 服务端 HTML；认证、提交、展示 | 会话密钥；读写 SQLite；**不持**模型和行情凭据 |
| worker | 从 SQLite 取 `queued` 任务，一次一个；取资料、调模型、写结果 | 模型与 TuShare 凭据 |

- web 和 worker 只通过 SQLite 的任务表交流，不再有私有 socket 接收器、令牌渠道和接口网关。
- 部署用本仓库的 docker compose：web、worker 各一个容器；web 只注入 `.env.web`，模型与行情凭据只注入 worker。worker 挂载宿主 `~/.pi`，按 pi 托管安装的 `current-version` 找运行时，pi 升级后无需改配置。
- SQLite 存全部结构化数据：公司、任务、模型调用记录、报告（结构化正文 JSON 字段）、事实与引文。PDF 按内容哈希存文件目录，库里记来源 URL、哈希和取得时间。
- 页面：首页（输入框 + 公司列表 + 进行中的任务）、任务进度、报告、公司档案、价格参考。纯服务端 HTML（原生表单、链接与 `<details>`），无脚本、无前端框架。

## 4 数据与模型

- **结构化数字**（营收、利润、现金流、资产负债、估值）走 `a-stock-lib` 的 TuShare provider。
- **PDF**：基础取证读取年报管理层讨论与分析；AI 通过工具列出年报、半年报、季报，检索并读取相关页，来源标识、页码和原文随证据保存。支持按问题检索业绩预告/快报及重大事项等临时公告标题，再读取选中 PDF；记录日期范围、关键词和是否截断，最多扫描 90 条，默认近 180 天、可回看至 550 天。预告与已实现业绩、中标与已确认收入分别解释，不宣称覆盖全部公告、新闻和非公开数据。
- 这一分工减少旧系统里大量表格解析规则（“%”表头、标题变体、晚出身份表等）。M0 用评估集的真实公司核对：报告需要的数字 TuShare 是否都有；没有的再考虑从 PDF 表格取。
- **M0 结果（2026-10-21，评估集 11 家）**：巨潮 11/11 取到年报和最新半年报；TuShare 营收、归母净利与年报一致（年报单位有元、千元、百万元三种，TuShare 统一为元）；`comp_type` 可在提交前识别银行（2）、保险（3）、券商（4）；年报 141–350 页，都有风险小节。据此 M1 的财务数字由程序从 TuShare 生成表格，模型只解释、不抄写数字；PDF 用于业务与风险引文。
- **模型**只通过现有模块调用 pi 运行时，provider 和模型继续由 `MODEL_PROVIDER`、`MODEL_ID` 配置。本批允许真实工具调用及上下文续接；不另引模型运行时或编排框架。

## 5 研究流程

首发流程：**取资料 → 成文 → 机械检查 → 独立复核**，最多两次修复。本批在同一 worker 内改为 **基础资料 → AI 选择补证/计算 → 回答与报告 → 原有核验与复核**。保留必要的基础资料避免遗漏风险；AI 自主决定探索顺序与何时结束。

- 程序检查引文与来源、期间、结构化数字及派生计算；模型复核论断是否被证据支持。计算结果可被引用，不要求派生值在原文里逐字出现。
- 新规则应解决已观察到的错误；可以删除失效规则。先用对应真实案例验证，不把跑完全集设为每次局部修改的前置条件。
- 首发流程最多 6 次调用。本批探索最多 12 轮、24 次工具调用、15 分钟探索预算（调用前检查，在途模型请求沿用单次与整体时限，取数沿用自身超时），另留原有核验修复空间；重复工具请求复用结果，耗尽预算时仅按已取得证据回答并明确缺口。单个补证工具异常保留诊断并记为缺口，允许使用已有资料继续。中断保留材料与错误，重启仍由用户重跑，不加恢复平台。
- **M1 评估（2026-10-21）**：第一轮（只修复一次）非金融 5/10 通过；改为最多修复两次后 8/9 通过，剩下 1 家是跨列表格引文被误判，加上 `-raw` 文本匹配后通过；另 1 家巨潮断连，加重试后通过。合计 10/10，每家 50–190 秒、2–6 次调用；招商银行 2 秒内按范围外拒绝。

## 6 状态与正确性

- 任务状态只有 `queued`、`running`、`done`、`failed`，外加当前步骤。worker 崩溃或重启时，把 `running` 的任务标为 `failed`，用户可以重跑。
- 每次模型调用保存请求、响应、用量和耗时，用于排错和统计成本，不用于恢复。
- 表单重复提交：页面带一次性提交编号，同编号只建一个任务。
- PDF 下载时记录哈希，此后信任数据库，不在每次读取时复验。
- 不做：报价比对、预算预占、outcome_unknown、代际 ID、渠道令牌与每日限额、批次目录锁与哈希台账。

## 7 安全

保留便宜且必要的：

- GitHub OAuth，只放行本人的数字 ID；会话由服务端登记，`HttpOnly`、`Secure`、`SameSite=Lax`，8 小时到期，可退出。
- AI/脚本验收用 `python -m a_share_research.login_token` 在宿主或容器内直接签发短期会话（1–480 分钟），不经 HTTP；能执行它已等同于有数据目录权限。
- POST 校验 CSRF 令牌和同源；Host 校验；CSP `default-src 'self'`；私有页 `no-store`。
- Jinja 自动转义；模型文本、引文、来源 URL 只作纯文本。
- web 进程不持模型和行情凭据；凭据只在 `.env`（不进 Git、不进镜像）。

首发不做：管理员密码登录、IP 白名单、MCP。

## 8 开发方式

- **Claude 主导**：自己设计、写代码、自查，直接提交。只有真正有争议的大分叉才用 `adversarial-decision`。不再用“Codex 编码 + agy 审查 + Claude 修复”的流水线。
- **真实数据**：开发和验证都跑真实付费研究，不写 mock、不造合成数据，不计成本。
- **评估集**：10 家真实非金融公司：600519 贵州茅台、000858 五粮液、600900 长江电力、601088 中国神华、000333 美的集团、002236 大华股份、603606 东方电缆、600276 恒瑞医药、002594 比亚迪、600309 万华化学，另加 600036 招商银行作为范围外反例（代码里的 `EVAL_SET`）。开发先跑受影响案例和一个原有正常案例，最终候选跑一次全集，记录通过率、耗时、调用次数，抽读报告；新失败或改动才触发适用补测。
- **测试**：只给确定性代码写少量测试（引文匹配、数字核对、价格计算），输入取自真实采集的 PDF 和行情。不做多屏幕尺寸回归矩阵；每个里程碑用真实浏览器在手机尺寸走一遍主流程。
- **文档**：README 负责入口，本方案负责产品与现有流程；按 2026-10-22 用户请求，新增项目契约、路线图和实施计划作为三项目共用正文。各类内容只维护一处，其他仓库链接引用；普通维护更新现有 owner 文档，不新增重复计划或台账。

## 9 不再踩的旧坑

| 旧坑 | 这次怎么做 |
|---|---|
| 研究流程两周内 v1→v4 重写四次，59 个 fix 多是单个样本线上失败后补规则 | 定向真实案例修复，最终候选看固定全集结果 |
| 产品方向三次转向（个人工作台 → 波段观察 → 研究助手），做完的功能又退役 | 首发只做第 1 节三件事，其他按实际使用再加 |
| UI 从 Flet 换到 Jinja，字体与 CDN 反复折腾 | 从第一天就用服务端 HTML |
| 文件批次当数据库：每次读取复验哈希、内存投影缓存、全量扫描 | SQLite 是唯一结构化存储 |
| 单家公司研究也冻结全市场清单 | 只取被研究公司的数据 |
| 线上接收器从开发工作树运行，每次升级要停服授权 | 线上跑构建好的镜像，开发改动在重建前不影响线上；只从已提交、已推送的 main 重建发布 |
| 多 agent 流水线：stdin 卡死 3 小时、配额 429 | Claude 直接开发 |
| 多个模型运行时来回试验 | 只用 pi 一个运行时 |
| 每个请求都要确认成本、每次升级都要授权 | 常设授权，只有上线切换要授权（见 AGENTS.md） |
| 文档比代码长，处处“不等于……不构成……” | 文档分工明确、正文单一来源；已实现能力以代码为准 |

## 10 里程碑

1. **M0 打通真实数据**：用评估集里的一家公司跑通 a-stock-lib 取数、巨潮 PDF 下载与文字提取、pi 单次模型调用；核对 TuShare 是否覆盖报告所需数字。
2. **M1 命令行研究**：`python -m a_share_research.research 600519` 端到端生成报告并写入 SQLite。评估集达标后进入下一步：非金融公司至少 8/10 生成通过复核的报告，抽查无编造数字。
3. **M2 网页主流程**：输入 → 进度 → 报告 → 公司列表，手机可用，GitHub 登录。在本机非生产端口用真实数据走通。
4. **M3 价格参考**：移植 a-stock-tracker 的 `price-reference-v2` 算法（5 个交易日有效期、过期隐藏价位），只算用户选的公司；前复权改用 TuShare 复权因子，不再从前收盘价推断除权。
5. **M4 上线切换**（唯一需要授权的步骤）：在宿主机用 docker compose 启动新系统，切换域名与 Nginx，停止旧系统受理新请求。旧系统的数据、容器和代码原样保留，不迁移、不删除。
   - 结果（2026-10-21）：v1.0.1 上线，stock.keyi.win → `a-share-research-web:8620`。当天下午部署改为本仓库 docker compose 编排 web 与 worker 两个容器，数据在 `~/a-share-research-data`；独立 release 目录和宿主 systemd worker 停用。旧系统数据、镜像和代码保留。

## 11 上线后计划（2026-10-22 更新）

上线后的功能只按真实使用加，每一项都先说清依据。本节维护产品候选；跨项目能力的阶段、工作包与状态只维护在[路线图](roadmap.md)和[实施计划](implementation-plan.md)，实现、验证与部署状态分别记录。

1. **运行时路径修复（已完成）**：10-22 pi 托管安装导致旧路径失效，worker 已改为跟随 `current-version` 查找运行时。当次容器评估非金融 10/10 通过，招商银行按范围拒绝。后续身份、重放及审查修复也已部署；当前状态与回退见[部署记录](implementation-plan.md#当前部署)，本批自主研究见[推进顺序](implementation-plan.md#下一批推进顺序)。
2. **已确认的本批需求**：按用户 2026-10-23 请求，优先实现人与 Agent 共用研究入口、自主补证与计算、追问及纠错。先更新文档，由 Claude 独立审查，通过后落地；不再等只读接口使用量来决定是否允许 AI 探索。
3. **其余候选功能**：
   - **金融股**：旧系统招商银行被拒两次，是唯一有未满足需求记录的一项。银行、保险、券商的财务表和风险小节都不同，需要单独的财务表和评估子集（每类 2 家）。
   - **MCP 与客户端接入**：先用 JSON API 真实提交和消费研究；宿主确需 MCP 时再加薄适配，不恢复旧 Tracker 接口，不修改全局客户端配置。
   - **初筛**：旧系统 4 次全部失败，暂无需求证据，最后考虑。
