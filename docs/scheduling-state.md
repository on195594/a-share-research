# 定时任务状态收归服务端

止损、日报、月度对比、顾问和月批任务由 Hermes 触发并投递，运行状态由服务端保存。此前宿主 JSON 保存待查编号和去重键，服务端另存政策激活和评估回执。排查一次漏报要对照这两处和 Hermes 执行记录；观察期内 15 次失败中有 13 次发生在发布后五分钟内。这项改动改善通知可靠性，不改变研究判断或记分。

## 状态归属

- **服务端记一次运行，客户端不做对账。** `scheduled_runs` 以凭据、任务和上海时段为唯一键，保存政策激活、评估或扫描编号、正文及脱敏失败原因。遇到超时，客户端用原凭据和时段查回，不另建请求。定时评估用当时生效的政策；采集中切换激活且确定旧评估未写入时，服务端才换请求编号重试一次。交互式工具仍校验调用者给出的预期激活编号。
- **按确认去重，不按生成去重。** 脚本先输出正文，再确认运行。下一轮从已确认记录继承止损档位、机会或月批事件；确认失败时可能重推，不能把未确认的提醒当作已送达。服务端不持 Telegram 凭据，`acked` 只证明脚本已处理回执，最终投递仍要查 Hermes。
- **跨期不补造当期结果。** 已就绪的日报可查回原文，未就绪的不在次日补算。跨日扫描先补已提交的披露，不以昨日机会代替今日评估；历史周没有已生成的摘要就过期。各任务的时段、查回和输出规则见 [Hermes 手册](../ops/hermes/README.md#定时运行与确认)。

## 结论与交接

业务脚本只保留任务锁，不再迁移宿主待查文件或并行维护旧状态机。维护证据（`~/.local/share/a-share-research-evaluations/` 下）：`sched-state-20261123/`、`sched-seg3-20261123/`。

回退前必须交接未确认运行，不能只换回旧脚本。操作见 [Hermes 回退手册](../ops/hermes/README.md#定时任务状态段-3-回退)，可用镜像与数据库基线见[当前部署](implementation-plan.md#当前部署)。
