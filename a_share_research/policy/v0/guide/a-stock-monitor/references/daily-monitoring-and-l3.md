# 日常监控、止损与 L3 全量核查

仅用于日常/异常下跌/季报重大公告的步骤2与2.5。主 `SKILL.md` 的 W1、升级路由和安全边界始终优先；动作优先级以 runtime 输出与 [决策表](decision-table.json) 为准；本 reference 不形成第二套交易出口。

`research_thesis_review` 是 Research 持仓论点卡的待复核入口：引用升级项的事件标题/类型，按日常异常、公告、活动预警或 L3 资料核对公开证据；需要报告时按 [Research 服务](research-service.md) 读取卡片对应 `report_id`。卡片待复核本身不等于 L3 证伪，不冻结、不产生交易候选、不自动写入 L3；原有止损、预算和门禁仍按本轮快照执行。待复核卡的区间与回报只展示，注明“区间暂停解读”。

## 步骤2：日常监控与止损触发

每季报/重大公告时搜索：`[股票] 最新公告 季报` `[股票] 大股东减持`

**⚠️ 持仓股当日异常下跌即时核验**：已持仓股票单日跌幅 ≥3%、或明显弱于所属行业指数 ≥2pts 时，必须当日立即搜索 `[股票] 最新公告 异动 原因 减持 监管问询`，区分"已公告利空 / 行业同步 / 无公开原因"三种情形。公开信息可即时查证时，不得以"明日再查"为由推迟；若当日未见公告，须写明"截至查询时未见公告"并给出次日开盘前复核节点。

⚠️ **判定"行业同步"须使用当日（同一交易日）的板块/可比同业涨跌幅数据，不得用多日/多周趋势代替当日横截面比较**：若当日无法取得可比板块/同业当日涨跌幅数据，不得直接判定"排除行业同步"，应如实标注"截至查询时未取得同日行业对比数据，暂不能区分行业同步与个股异常"，并明确给出次日开盘前的复核节点。本项仅用于异动原因的事实分类，不构成对已触发机械规则（如个股notes中预设的价格纪律）的新增豁免——即使后续查明确属行业同步，也不得据此推翻已按机械规则触发的动作（以当前快照与既有结构化条件为准）。

### C框架止损前置检查（C框架持仓必做，其他框架可选）

**在执行任何价格止损前**，先回答三个问题防止周期底部误止损：

| 问题 | 判断依据 |
|------|---------|
| Q1：商品价格当前处于周期几位？ | 仅核验商品周期证据；不重启首次投研或读取额外账户状态 |
| Q2：公司整体盈利是否已转负？ | 区分「品种亏损」vs「公司合并净利润转负」 |
| Q3：买入时的核心逻辑（L3）是否已被证伪？ | 逻辑证伪 ≠ 价格下跌 |

**⚠️ Q1/Q2/Q3 三态核查要求（先于下方判断规则执行）**：Q1/Q2/Q3 每项须先按各自实际语义独立核查明确状态，不得笼统套用同一组"触发/未触发"标签：
- Q1（商品价格周期位置）→ `底部区` / `非底部区` / `数据不足-待核实`
- Q2（公司整体盈利是否已转负）→ `已转负` / `未转负` / `数据不足-待核实`
- Q3（L3核心逻辑是否已被证伪）→ `已证伪` / `未证伪` / `数据不足-待核实`

不得把"没有最新数据证明已转负"处理成"未转负"——数据不足与已核实排除是两种不同状态，须分别列出。下方判断规则的 AND 逻辑仅在 Q1/Q2/Q3 均取得已核实的保护性结果（Q1=底部区 且 Q2=未转负 且 Q3=未证伪）时才成立；任一项为"数据不足-待核实"时，不得判定周期底部保护适用，须先升级核实；若在执行节点前仍无法核实，默认不适用周期底部保护，按正常价格止损规则执行（不因保护结论未决而豁免止损）。

判断规则：
- Q1=底部区 **且** Q2=公司未转负 **且** Q3=逻辑未证伪 → 标注⚠️「疑似周期底部误止损，建议减仓50%而非清仓，保留等待反转」
- Q2=净利润已转负 **或** Q3=逻辑已证伪 → 执行正常止损，不受周期保护

**⚠️ 周期底部保护的执行节点澄清**：本保护规则的效果具体体现在第二档止损线（从本轮 `monitor-snapshot` 持仓项的 `stop_loss_20` 列读取的实际价格，该列按框架不同而不同，非固定成本×0.80）：若保护条件成立，第二档触发后的复查决定不得超过"减仓50%"这一幅度（即不得清仓），维持50%仓位等待反转验证；若保护条件不成立，复查后可按正常判断决定是否清仓。第一档止损线本身只触发强制复查（无直接卖出动作），保护规则在此节点的意义是确认复查按正常流程进行，不因保护成立而跳过复查、也不因保护成立而额外加仓。

> ⚠️ **煤炭/金属股价格口径**：Q1判断商品价格周期位置时，引用现货价须标注"长协占比约X%，长协结算价通常低于现货10-20%且有1-2个季度财报滞后"，不得用现货价直接判断公司当期盈利是否已经改善（可能仍未传导到报表，误判Q2）。

### 止损机制

#### 论文破灭型止损（优先级最高，适用所有框架；状态机）

只有以下两类可以进入“已确认触发”：

- 建仓时结构化记录的某条 L3 数值条件达到阈值；
- 核心业务、监管可持续性或管理层诚信被确定性证据否定。

通用财务恶化指标——ROE连续2个季度均较上年同期下降>5pts，或扣非归母净利润
连续2个季度同比负增长——只产生“论文破灭候选信号 + 红色预警”，不再单独等同于
论文破灭。它们用于启动框架专属复核，避免把增速为负、盈利水平转负和竞争优势破坏
混为一谈。

状态路径：

- **结构化 L3 数值条件**：核实口径、报告期和计算无误后，直接标为 `triggered`，
  输出该 L3 预设动作；
- **主观/事件条件**：`候选信号 → 待确认 → 已确认触发`。须列出可查证事实、
  原始来源、与原始 L3 的对应及反证，至少间隔1个交易日复核；
- **通用财务恶化指标**：`红色预警 → 框架专属复核`，不得直接清仓。若同时触发
  原始 L3，才升级为论文破灭；没有可追溯 L3 时按“论文不可验证”处理。

在任何 `triggered + reduce/exit` 输出前，必须确认：L3绑定当前活动论文、未退役、
scope/action合法、`materiality_basis`可追溯、临时出场规则已定义动作幅度和下一复核节点，
且证据报告期匹配。任一失败，输出“触发文本成立，但交易契约无效/已过期，冻结交易并重做
论文”，不得给出卖出股数。`non_core` 只能配置 `review`；治理类 `exit` 必须对应集团级确定性事实；
`core_driver + exit` 的重要性依据必须说明其为何是主要利润/现金流来源及所需确认期数；
`aggregate + exit` 必须基于集团或主要利润引擎的盈利、现金流或资产负债表指标，不得只用价格或非核心分部收入。

**C/D 周期框架专属复核**：

1. 独立核验周期/量价位置、盈利水平、原始L3，数据不足不视为保护成立；
2. 若仍盈利、周期处底部且L3未触发：维持红色预警，缩短到月度复核，不因负增长清仓；
3. 最近单季扣非转负，或核心商品/来水/电价等量价驱动连续两个报告期跌破原始L3线，
   或分红自由现金流覆盖率连续两个报告期<1：视为原始论文的强证伪证据；
4. C/D 的保护只改变通用财务恶化信号，不覆盖已触发的个股L3、监管或诚信事件。

（暴跌恐慌下，分析者可能主动放大证据、把"竞争加剧"解读为"核心逻辑被否定"，为恐慌性清仓找程序化借口——这正是"候选—待确认"分支要防止的道德风险，不得跳过。）

### P0-P3 运行时硬门

价格或加仓判断前读取基本面 payload 的 `regulatory_gate`、`roe_structural_gate`、`cash_flow_gate`。状态为 `blocked` 时冻结新增风险敞口并生成红色复核；`incomplete` 或 `review_required` 时生成红色复核，加仓上限降为 `position-size` 首批（`tranches[0]`），补齐前不追加后续批次（[2026-11-04 规格](https://github.com/on195594/a-stock-agent-skills/blob/master/docs/specs/2026-11-04-proactive-decision-spec.md)；runtime 状态与升级项不变）。均不自动清仓。P3 只包装实际 `stop_loss_20` 第二档：全市场有效跌停数严格超过500家时，使用同一 `holding_alerts` reason code 延迟一次24小时；前置窗口不输出股数，停牌/一字跌停/无效报价保持 `untradeable` 或 `incomplete`，不得伪造成交。

**基本面止损**（配置型持仓优先使用）：
- C框架：商品价格逻辑根本性破坏 → 考虑清仓；分红能力下修>30%且无回升迹象 → 触发复查
- D框架：股息率vs国债溢价跌破100bps → 考虑减仓
- 所有框架：ROE连续2季度下滑>3pts → 黄色预警；核心业务逻辑证伪 → 红色预警

**价格止损**（交易型持仓，C框架须先完成前置检查）：

⚠️ **止损线按框架不同**：复用本轮 `monitor-snapshot` 中的 `stop_loss_15` / `stop_loss_20` 实际价位及其来源；字段名不表示固定-15%/-20%。缺失、口径冲突或框架未确认时按 runtime 缺口升级核验，不在 Skill 中重新计算系数或重复读取持仓。

⚠️ **止损系数越宽的框架，须在仓位占比上主动核对是否失衡，不能只放宽跌幅容忍度而不管仓位大小**：建仓仓位以 `position-size` 按止损风险预算给出的股数为准（止损越宽，同等预算下股数越少）；若在组合层面分析（步骤0-1/0-1a）中发现某持仓所属框架止损深度明显宽于同组合其他持仓（如F/C框架 vs B/D框架），但其仓位占比却相近或更高，须在本次分析结论中标注"止损深度与仓位占比可能失衡"，并提示是否需要在后续调整中降低该持仓仓位——不强制立即执行，仅作为必须输出的风险提示，不得因为止损线已经写清楚就默认仓位配置也已经隐含风险平衡。

- 第一档（`stop_loss_15` 对应线）触发：在 Monitor 内按该持仓框架完整复查基本面、估值与 L3，不重新路由到首次投研
- 第二档（`stop_loss_20` 列对应线）触发：目标减仓50%，先用
  `sell-holding` 的申报规则计算最接近且不超过当前持仓的可执行股数，用户确认成交后
  再写账本；复查后决定是否清仓
- **季末缓冲已停用**：原“季末最后1-2个交易日且权重股普跌”缺少可复算样本和阈值，
  在历史回放完成前不得作为价格止损豁免。

**⚠️ 价格预警与 L3 结论分离**：价格跌破自设预警位（如成本×0.82 或任意价格提醒线）只是立即执行 Step 2.5 L3 全量核查的**触发信号**，不是 L3 失效的证据，也不是止损执行命令。L3 结论由基本面条件决定，与股价无关。操作上应明确区分两个价格：
- 自设预警价（示例性质，如成本×0.9附近，具体比例可自行设定，仅作提前关注的心理提示线，非强制计算值）：触发做 L3 全量核查
- 止损执行价（即该框架的第二档止损价——直接从本轮 `monitor-snapshot` 持仓项的 `stop_loss_20` 列读取的实际价格，该列存储的是价位而非系数，不是固定"成本×0.80"）：若 L3 同时失效则执行；若 L3 未失效则执行"第二档→减半仓"规则

不得将两个价格混写成同一行动节点（"跌破39元止损/做L3"），必须分两步写清楚。机械触发规则不得事后追加未预设的例外；动作仍服从 runtime 和决策表。

### 预警机制

黄色预警（记录，关注不操作）：ROE下滑>3pts｜再融资摊薄｜核心高管离职｜机构持续减仓
红色预警（触发复查，考虑减仓）：2项以上黄色同时触发｜商誉减值｜大股东减持

⚠️ **每次监控核查前先执行 `$CACHE alerts <代码>`**。活动预警以稳定
`reason_code` 去重，并具有 `active/pending/resolved` 生命周期；不得再按
`analysis_results.flags` 的历史记录条数计数。每项活动预警必须核验：

1. 当前证据是否仍成立；
2. 是否到达 `review_due`；
3. 已消除时用 `alert-resolve` 写入解除证据；
4. 证据不足时保持 `pending`，不得静默丢弃。

只有 `holding_deterioration` 类黄色预警计入“2项→红色”门槛；
`entry_valuation` 和 `unverified` 分别用于买点提示与待核实事项，不累积成减仓压力。
旧版 flags 仅作迁移核对，不再是当前状态源。命令见数据操作附录。

## 步骤2.5：L3 失效主动检查（定期审视，不依赖价格触发）

每季报后或有重大行业新闻时，按 `evidence_cadence` 主动检查 L3：季报只能裁定 `quarterly`/`event` 行；`semiannual`/`annual` 行仅作检查点，记录方向并保持状态；`unspecified` 行须用户通过 `a-stock-cache --confirm-write l3-update <id> <status> <as-of> <证据> [下次复核日期] --evidence-cadence <值>` 分类后，才能用季报改变状态，不自动回填旧行。

财务核对使用 `a-stock-fetch quarter <代码> --json` 的 TTM 与同比数据，不将中期数据年化。资产负债表增速以去年同一期末同比（`yoy_same_period_end`）为主；较年初（`vs_year_start`）只可明确标为季节性对照，不与收入同比混比。任何 Agent 自算值必须标为“估算”，不能单独据此把 L3 设为 `triggered` 或 `not_triggered`。

1. 搜索：`[股票] 季报 最新 行业动态 竞争格局`
2. 对照建仓时写下的 L3 条件，逐一验证：
   - L3 条件是否已发生？（是 → 触发论文破灭型止损）
   - L3 条件是否更接近触发边缘？（是 → 升级为黄色预警，缩短复查周期）
   - L3 条件是否已被新信息强化（更难证伪）？（是 → 论文更稳固，记录并继续持有）
3. 按上述证据频率列出待确认的 `l3-update`（上次验证日期 + 结论，检查点保持状态）；用户确认后才写入，不得更新退役行

**⚠️ L3 全量核查强制要求**：L3 核查结论必须逐条列出所有 L3 可证伪条件的当前状态（`触发` / `未触发` / `待观察（原因）`），附数据依据与来源日期；绝不能只核查最显眼的一条（如煤价）就直接下"L3未触发"结论——其余条件若本次无数据可判断，须明确标注"待观察（等XX报告/数据）"，说明等待何种报告/数据。按实际持仓论文逐条列出，不得省略任一条件。

**⚠️ "待观察"须先尝试核查，不得默认套用**：判定某 L3 条件为"待观察"前，须先区分该条件是否需要连续多期数据（如"连续两个报告期净息差同比下降"）还是仅需当前单一数值即可判断（如"资本充足率<10%"、"资产负债率"等即时可查指标）。后一类指标必须先尝试实际核查（WebSearch/fetcher），核实结果明确写为`未触发`或`触发`；只有确认无法获取当前值、或指标本身确实需要跨期比较且暂无对比数据时，才可标注"待观察"。不得把多个性质不同的指标笼统归为同一"待观察"清单。

**⚠️ L3记录引用不可追溯的历史版本视为未核查**：若持仓 notes 中的 L3 条件仅以"沿用 YYYY-MM-DD 版本"等方式引用，而该引用内容本身在 notes 中不可见/不完整（无法逐条列出具体条件文本），本次核查必须视为"L3 尚未核查"，不得直接给出"继续持有"等清洁结论。处理方式：①若能恢复，按以下顺序检索（找到即用，不需要逐一穷尽）：(a) 当前持仓 notes 中是否已有更早的完整记录；(b) `cache.py check <代码>` 返回的历史分析缓存；(c) 其他版本化原始存档（如聊天记录、外部笔记）。标注为"恢复的原始 L3"并保留原始来源和日期。后续才出现的公开信息（如今天才查到的新闻）不能证明"建仓时已存在"，不得作为恢复依据，只能走②"本次新设的监控条件"，这不违反步骤1"建仓当日必须写下买入论文、不得事后补写"的要求，因为恢复的是已存在的历史记录，不是新创作；②若无法找到任何可追溯的原始记录，不得声称重建结果是原始买入论文——只能标注为"原始 L3 记录缺失、历史论文不可验证，本次新设的监控条件（非建仓时原始论文）"，同时明确记录这一限制。无论选择①还是②，均须完整执行下文"L3 待定义/待观察时的操作边界"要求的三项输出（待补全条件、下次验证节点、临时出场框架），不得仅以本条的限定语替代该操作边界的完整要求。

**⚠️ L3 待定义/待观察时的操作边界**：缺失数据不等于已排除/未触发；明确待补全条件、下次验证节点和临时出场框架。未核验状态不得包装成“继续持有”等清洁结论，临时规则仍需明确授权。

**等待财报的判断树要求**：若操作建议包含"等中报/等季报/等经营数据"，必须同时预设判断树，格式为：`指标A达到/高于X → 加仓或持有；指标A低于Y或连续恶化 → 减仓/止损；落在中间区间 → 维持仓位并在N日内复查`。判断树至少覆盖原 L3 条件中最关键的 2 项。若无法设定阈值，须说明原因，不得补造。Research 的新 `add_trigger` 或旧“等证据” `trigger` 只作参考，不阻止首批；按 [Research 服务规则](research-service.md) 限为 `position-size.tranches[0]`，目标期间披露达标且更新有效研究确认前不加后续批次，未达标复核是否减仓。

**与论文破灭型止损的区别**：止损是被动触发（条件已满足），L3 主动检查是在触发之前的预防性审视。
